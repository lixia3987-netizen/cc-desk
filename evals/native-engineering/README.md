## v2 的 Windows 模块入口修复

v1 的选定回归命令将 `require.resolve('tsx')` 返回的 Windows 绝对路径直接传给 Node `--import`，盘符会被误认成 URL 协议，导致测试启动前报 `ERR_UNSUPPORTED_ESM_URL_SCHEME`。v2 将该入口转换成 `pathToFileURL(...).href`。任务基线、任务文本、全部补丁、oracle 及原有断言逐字节保持；其他变化限于新版本标识、三条注释的中文说明与版本文档。

v2 固定摘要为 `ec64644c0ee45495e0968c0859d483bf0c37fc22029c7a5f55883e6f0c0d6624`，同样覆盖 16 个材料文件；没有复制 v1 的历史 `validation.json`。旧批次继续使用下面的 v1 身份，新结果须写入独立批次和新的现场证据。跨平台入口修复本身不代表已通过真实模型、图形界面或平台验收。

`v1/` 是历史冻结材料，任务基线为 `b45bd0623d2a44a2878c46d4701fa4b388c7d9be`，材料摘要固定为 `7ac65759b84e3946f632a931ff7bece2e50051fc25b2ee9a5e0c23bd2cbfba8a`。摘要覆盖按路径排序遍历的 16 个文件的原始字节，包括任务、验收器、注入补丁、参考补丁和自检程序；仅排除派生的 `validation.json`。

冻结材料中的原有英文注释属于历史字节材料例外。当前生产代码和新注释继续使用中文；不要在 `v1/` 内翻译注释、调整行尾或加入本说明，否则原材料身份会改变。未来若需修改任务、代码、补丁、验收规则或材料文字，应创建新版本并独立冻结摘要、生成新的现场证据，不能把新摘要覆盖到旧版本或历史结果中。
