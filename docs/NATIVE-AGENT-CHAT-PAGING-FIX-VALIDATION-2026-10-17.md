# Native 会话分页与刷新修复：Windows 复验

日期：2026-10-17。修复基线：`b1377d7f59916fabc3690eaeedc7b97eab3e41bb`。分支：`codex/native-chat-paging-refresh`。

依据：[原静态分析](NATIVE-AGENT-CHAT-PAGING-ANALYSIS.md)、[修复前实机验证](NATIVE-AGENT-CHAT-PAGING-VALIDATION-2026-10-17.md)。原分析保留原文；其中推断的修正以实机报告为准。

## 实现范围

- 首屏不足一屏时自动补充旧页；到达顶部时向上滚轮也能触发分页。自动补页限定单一方向和最多 8 次读取；无进展、达到容量边界或读取出错时停止，避免来回翻页。
- 临时不可读的空且不完整分页结果作为可重试错误处理，保留已有消息及游标。重试沿原读取方向和锚点继续；完整的空页仍可确认真正的记录边界。
- 长历史保留 1,000 条 / 8 MiB 前端容量限制。旧页保留首部、较新页保留尾部，且快照补入较大正文时沿用同一裁剪方向；不会把缺少中间记录的历史与实时尾页直接拼接。
- 普通历史阅读也提供“查看较新消息”“返回最新对话”“跳到最新消息”，脱离尾部时显示较新消息提示；到达完整开头时显示明确边界说明。
- 修复虚拟列表首次安装滚动监听早于父容器 ref 就绪的问题；消息窗口变化后重新读取实际视口，避免记录数量增加但仍挂载旧尾部、顶部出现空白。行挂载完成后释放临时目标锁；主动跳转退役旧锚点恢复，避免滚动条到底但列表仍锁在中部。
- 共享状态读取失败后按 5、15、30 秒退避重试，之后维持 30 秒；成功、释放或会话身份变化会取消旧计时器。快速事件刷新仍保留熔断限制，被动恢复不依赖再次点击或新的变更通知。
- Native 文本增量通知按 50 ms 合并；审批、终结及状态变化及时发送。通知直接读取任务状态，不再为每段文本复制整个快照；旧计时器校验原对话身份。
- 展示日志按约 256 KiB 分块写入，保留同步落盘、原子发布及恢复行为。已提交的投影通过相同事件重放规则载入有界内存，避免同步重读刚写入的文件。

本轮没有实现增量投影。新账本头仍全量重放、重写，旧页索引仍可能因文件替换而重建；长会话的复杂度问题需另行处理。

## 环境与证据边界

Windows x64 / Intel Core i7-13700KF；真实 Electron 44.4.3 窗口运行重新构建的桌面应用。原生输入通过 Computer Use，DOM、IPC 与截图通过 Playwright Electron 观测。最大化视口为 2560 × 1369、DPR 1。

装置 A 为 36 个折叠工具与用户/最终答复，共 38 条；装置 B 为 110 个工具与用户/最终答复，共 112 条。使用正式 NativeRunStore 写入合法离线账本，再由正式 NativeProjection 发布，未实际执行工具或请求外部模型。压力历史超过默认执行输入预算，验证的是展示容量与恢复路径。现有用户会话仅复制到隔离目录，不复制凭据和待执行队列。

故障检查在隔离目录临时移走展示日志，并在 finally 中恢复、核对 SHA-256；这不是自然触发 Windows 文件竞争的证据。Electron 回归额外注入状态读取失败，以及延迟一页真实分页响应，成功返回值均来自正式读取实现。

截图、IPC 数值、隔离账本及性能记录保留在本机忽略目录 `test-results/`，不随提交发布用户会话、凭据或原始大文件。

## 投影性能复测

同一机器相邻执行旧 `b1377d7` 投影和修复后实现，使用相同正式账本、相同依赖及进程内计数。以下是新增一条记录后 hydrate 的三次中位数，单位 ms：

| 单条正文 | 记录数 | 旧实现 | 修复后 |
| --- | ---: | ---: | ---: |
| 512 B | 50 | 9.741 | 5.675 |
| 512 B | 250 | 23.508 | 11.384 |
| 512 B | 1,000 | 76.919 | 33.812 |
| 8 KiB | 50 | 12.714 | 9.276 |
| 8 KiB | 250 | 42.880 | 30.825 |
| 8 KiB | 1,000 | 285.354 | 178.287 |

1,000 条规模的逐行写调用由 2,004 次降为约 4 / 34 次（分别为 512 B / 8 KiB 装置）；发布后同步文件读取为 0，同步落盘仍保留。连续 200 个文本增量加一次显式 flush 仅产生 1 次 changed、0 次 snapshot；计时覆盖 flush，未把尚未触发的计时器误算为零通知。

这些数字包含热文件缓存、磁盘和机器负载，不是模型吞吐或跨机器性能承诺。修复前较早一轮的 149 ms 与本轮相邻旧实现 285 ms 采样条件不同，不据此宣称绝对速度或回归。原始记录：`test-results/paging-validation/projection-bench-baseline-current.json`、`projection-bench-after.json`。

检查期间修复了三个既有测试装置问题，生产能力限制与判定未放宽：

1. Windows 不允许覆盖仍打开的预览文件。替换竞争注入移到真实句柄关闭后、预览返回前，仍由读后版本核查拒绝旧内容合并；读中追加场景保留。对应 8 项测试通过。
2. 自动压缩装置的 50k 预算在现有工具定义和系统指令下过于临界，下一轮再次触发摘要。隔离的 `b1377d7` 基线同样失败。装置改为 55k 留余量，原“7 个请求、仅 1 次摘要”断言保留，完整 3 项通过；没有修改自动压缩产品逻辑。
3. 严格 Skill 继承装置受系统 `core.autocrlf=true` 影响：子工作树将 LF 的 168 字节技能文件改成 CRLF 的 173 字节，真实字节身份检查正确拒绝，隔离基线同样失败。仅为测试仓库设置 `core.autocrlf=false`；一次冻结、三并发、报告及账本断言保留，单项和最后组合回归均通过。

隔离基线及诊断位于 `test-results/paging-baseline-check/`、`test-results/paging-auto-compaction-diagnostic/`。本次没有验证安装包、外部模型服务、跨硬件表现或全部自然并发竞争。
