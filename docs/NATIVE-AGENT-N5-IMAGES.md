# N5-01：Native 显式图片输入

日期：2026-09-29（北京时间）。开发基线：`dev/native-agent@3b0e99cb6ae7a429b4233a6320eef7f52d2946c1`。

用户已要求跳过配置兼容性确认，先继续功能开发，兼容性问题后续处理。本批实现 Native 会话的显式图片输入，实际服务识图、Electron 交互和平台行为另列为 [RA-29](NATIVE-AGENT-RUNTIME-ACCEPTANCE.md)。E0-03 仍未执行；不再把提交 cc-switch 配置作为功能开发前置条件。

## 交付范围

- 复用已有附件选择、拖入、草稿、队列持有和会话删除流程。仅发送用户显式选入当前会话并点击发送的图片，不读取任意项目媒体、不自动截图、不增加屏幕控制或 MCP 观察工具。
- Native 首批支持 PNG/JPEG，最多 4 张，合计不超过 1 MiB；读取实际文件签名和尺寸，单边不超过 4096 像素，总像素不超过 16,777,216。Claude 的原有附件类型与额度保持原样。
- 宿主核对当前会话附件清单、普通文件及稳定文件身份，通过有界读取生成内容快照和 SHA-256；不允许跨会话路径、符号链接或硬链接替代。目录/文件检查属于应用边界，不是操作系统沙箱。
- 支持图片单独发送和图文一起发送。Responses 使用 `input_image`，Chat Completions 使用 `image_url`，仅携带本地快照的内联数据，不接受模型提供的远程图片地址，也不静默切换服务或协议。
- 图片内容进入提交身份及工作线程核验；同一个请求标识换图不能复用旧回执。排队确认记录保存当时图片哈希，实际发送时重新核对；等待或重启后文件改变会阻塞，不能悄悄发送新内容。图片元数据和完整模型上下文随原运行记录持久保存，重启不重新读取原始来源文件来重建已发送图片。
- 发送前显示所选文件名称、格式和大小；历史显示记录时的名称、类型、字节数和内容哈希。历史展示与普通对话导出仅含元数据，不展示或导出 base64 图片正文；这不等于图片内容已从本地原始记录中删除。

服务能力仍未验证。能选择图片、配置就绪或本地协议测试通过均不能证明所选模型能识图；实际接口拒绝时保留失败原因，待后续兼容性处理。

## 保留与运行限制

图片会随显式发送传给当前选择的模型服务，并保留在本机会话附件与原始模型记录中。移除尚未发送的附件只处理草稿；已经被队列/运行持有的文件继续按现有生命周期保留。删除会话使用既有附件及 Native 记录清理路径。

本批沿用现有保守 UTF-8 字节估算：内联图片的 base64 编码也计入本地输入预算。这是本地限制，不是服务商真实图像 token 或费用估算。默认 64000 的输入预算可能不足以发送截图；按界面提示缩小图片，或在运行配置中提高“输入预算（估算 tokens）”。实际输入/输出及费用仍以服务回执为准，未知保持未知。

首批**不支持含图上下文压缩**。手动压缩、发送前自动压缩和回合内压缩在需要处理图片时明确阻塞，不把图片编码作为普通文本交给摘要模型，不静默丢图，不把这类预检计成实际摘要调用。原始上下文与图片保留。图片会话继续受模型请求数、工具数、上下文字节、主动时长和磁盘容量约束；达到限制时给出停止结果，由用户调整输入或新建会话。

## 数据兼容与回退

无图提交沿用原有协议正文与输入摘要。新增图片字段为可选项，既有纯文本历史和队列保持原行为；带图片的队列必须具有确认时的内容哈希，缺失或不一致时停止，不能补造确认。

旧版本不具备含图上下文支持。回退代码前应保留会话附件和原始记录，含图会话使用支持此功能的版本继续，或新建纯文本会话；不通过删除图片字段、清空记录或重放旧请求来强制降级。
