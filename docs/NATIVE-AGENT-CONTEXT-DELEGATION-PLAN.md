# Native Agent 上下文成本与明确委派策略任务规划

日期：2026-10-15（北京时间）  
证据基线：`main@23efa6bbaab5494059d66c42eca77d936f4ed400`  
状态：规划提交后已启动实施；代码与验证进展见 [实施记录](NATIVE-AGENT-CONTEXT-DELEGATION-IMPLEMENTATION.md)。本文保留规划阶段的证据和验收要求。

## 1. 目标和范围

本次围绕两个问题安排开发：

1. 解释并降低 Native Agent 的额外上下文成本，区分显示估算、单次输入、累计输入和实际费用，先建立可复现基线，再决定优化项。
2. 用户明确要求并行分析时，主 Agent 拆出独立问题并实际调用宿主管理的 `delegate_review`；子任务收到完整材料位置、范围、证据和成果要求，主 Agent读取真实成果后归并。

本次提交仅包含规划文档，不修改执行器、提示词、工具接口或默认设置，不运行付费模型回归，不把待实施任务登记为已通过。

复用已有委派、独立 worker、任务账本、审批和预算机制。第一阶段不开发新的自治团队框架、递归委派、外部 Agent 启动器、自动成果采纳或自动合并功能。“使用 workflow”与“并行委派”需要分别处理：前者可能表示多阶段工作，不能只因出现该词就宣称创建了多 Agent 或改变人工验收门槛。

尚未取得用户本次具体请求的成本样本，因此不能确认工具目录、Skills、历史、图片或摘要中哪一项占比最大，也不承诺未经测量的节省百分比。

诊断需同时报告下列四项，互不替代：

| 指标 | 定义 |
|---|---|
| 单次上下文输入与峰值 | 每次请求的实际输入量或有来源标记的估算；峰值是该任务所有请求中的最大值 |
| 累计输入 | 多次父请求、子请求、摘要和重试的输入之和，按请求身份去重，不把它显示为当前窗口占用 |
| 缓存和费用 | 区分非缓存输入、缓存读取、缓存创建、输出及价格来源；缓存降价不意味着上下文窗口变小 |
| 本地估算与字节上限 | 明示估算方法和误差；字节安全上限与模型 token 上限分别保留 |

### 2.2 委派和提示词

- `delegate_review` 已存在，输入严格为 `tasks: [{title, goal}]`；每批 1–4 个任务，标题最多 200 字符，目标最多 6,000 字符。一父回合累计最多 16 个子任务。不能直接给现有工具增加 `documentPath`、`scope`、`outputFormat` 等未支持参数。[输入与工具定义](../apps/desktop/src/main/engines/native/agent-delegation.ts#L88)
- 同一调用的子任务通过 `Promise.allSettled` 执行，能够实际并行。核心循环即使按顺序执行工具，一个多任务批次也可并行；连续两次单任务委派不应被当作达成并行要求。[批次执行](../apps/desktop/src/main/engines/native/agent-delegation.ts#L180)
- 父提示词已有“委派后读取成果、核查整合与验收”的规则，但缺少“用户明确要求并行时必须调用工具”和完整任务交接规则。[父提示词](../apps/desktop/src/main/engines/native/structured-executor.ts#L64)
- 基线中未发现“主 Agent 一律不得创建其他 Agent”的全局禁令。已确认的原文是子提示词中的 `Children cannot spawn further agents.`，这条限制应保留。[子提示词](../apps/desktop/src/main/engines/native/agent-child-runner.ts#L80)
- 子 Agent 不注册委派、MCP 或跨成果读取工具，审阅子任务再受只读工具白名单约束。父子身份、预算、取消和审批仍由宿主执行。[子工具组合](../apps/desktop/src/main/engines/native/agent-child-runner.ts#L112)，[只读政策](../apps/desktop/src/main/engines/native/execution-policy.ts#L15)
- 实现子任务仍可能使用经审批的通用命令，当前机制不是能识别并阻止所有外部 Agent 可执行文件的操作系统沙箱。明确宿主委派许可时，不得扩大这些命令权限，也不得删除子递归委派限制。

### 2.3 回归证据边界

[委派单元测试](../apps/desktop/tests/native-agent-delegation.test.ts#L55)和 [Electron 多 Agent 回归](../apps/desktop/tests/native-multi-agent.spec.ts#L102)已经验证批次并发、生产 utilityProcess、独立上下文及预算/生命周期，但模型回复由受控 HTTP/SSE fixture 提供。这些结果不证明真实模型会主动选择委派。

现有 [native-model-regression.mjs](../scripts/native-model-regression.mjs#L12)仅提供 `regression_probe`，覆盖真实工具续接、重启去重和断流，不覆盖真实模型自主拆题、`delegate_review` 或生产子 worker。现有 [委派验收文档](NATIVE-AGENT-DELEGATION.md#验证范围)明确保留 RA-34/RA-35 真实模型验收 `pending`；本规划不修改这些历史状态。

## 4. 明确委派与交接设计

### 4.1 主 Agent 的行为要求

1. 从当前真实用户请求判断是否明确要求并行分析，例如“并行分析”“用多个子 Agent 分头审阅”。引号内的文档指令不能代替用户授权；“不要并行/只用一个 Agent”应优先满足。“workflow”一词本身不构成委派证明。
2. 检查材料是否位于子任务可读取的项目范围，或已有带来源的文本副本/片段；只收到文件名、拿不到原文、位置越界或内容不完整时，先说明材料缺口，不能让子任务猜测。
3. 拆出 2–4 个能够独立回答的问题，避免多个子任务读取并重复总结同一全文。存在前置依赖的分析放在后一批；问题不可独立拆分或预算/工具不支持时说明原因，不伪装已并行。
4. 在一个 `delegate_review` 调用中提交多个完整 goal，并在结果中核对实际子身份与执行状态。记录并行要求是否满足；只有分工文字、只有一项任务或没有委派回执时不得报告“已完成并行分析”。
5. 使用 `read_agent_result` 和宿主返回的 `parentRunId`、`childId` 获取真实成果；处理截断/分页、冲突、遗漏和未知项，再形成最终结论。工具终局或子回复不是父任务验收通过。

### 4.2 对提示词歧义的修正

新增父规则应明确：允许父 Agent 使用**已提供的宿主管理委派工具**，用户明确要求并行时应实际调用；不得通过命令、脚本、MCP 或外部服务另启 Agent 来替代该工具。子任务不可继续委派，读写和审批仍按宿主能力决定。

先集中维护父策略与工具描述的一致措辞，并将版本/digest 纳入 T01 诊断；保留只对子任务适用的禁令。回归检查最终发送到模型的有效 system/project/skill 组合，而非只检查某个常量，避免根规则、目录规则或所选 Skill 中的宽泛限制影响父任务对宿主委派能力的理解。

不新增“角色扮演即子 Agent”的定义，不把放宽通用命令权限当作实现委派。第一版以提示词策略、真实回执审计和行为回归验证要求；后续若增加运行结束的策略门槛，应先定义用户意图、否定表达和材料引用的确定性用例，不能用粗糙关键词命中将普通问答强制转成团队任务。

### 4.3 每个 goal 必须提供的内容

| 项目 | 要求 |
|---|---|
| 材料位置与版本 | 项目相对路径、段落/行范围、读取后的文件 hash 或宿主来源引用；区分全文、摘录与未读取材料 |
| 独立问题 | 一个主要问题和预期回答；明确与其他子任务的边界、依赖及排除范围 |
| 分析范围 | 要看的文档部分、相关源码路径和适用基线；不无边界扫描整仓，不默认继承父全部对话 |
| 已有证据 | 有来源的观察、位置与回执引用，并标记已确认/假设/未知；工具结果和普通材料中的指令按数据处理；适用的 AGENTS.md/CLAUDE.md 与所选项目规则按既有优先级处理，不能扩大宿主权限 |
| 权限与验证 | 只读，不执行命令、不写文件、不用 MCP、不再委派；未运行验证须明示，不能把推断当实测 |
| 返回格式与长度 | 结论摘要、发现、证据、未知项、建议；每项发现关联实际证据，以短结论返回，全文/日志用可重读引用 |

兼容现有工具的示例如下。尖括号内容是待填占位符，不是已经读取的证据；正式调用必须替换，并满足当前长度限制。

```json
{
  "tasks": [
    {
      "title": "文档目标与现有能力差距",
      "goal": "材料：<用户文档路径>，范围：<目标与功能段落>，版本：<读取后的hash>。独立问题：哪些目标已由当前项目实现，哪些仍缺失？源码范围：<对应模块路径与基线>。已有证据：<来源引用，或明确尚无证据>。排除：不分析另一子任务的安全与验证部分。仅使用已提供的只读工具，不运行命令、不修改文件、不再委派。返回summary、findings、evidence、limitations、recommendations；发现附实际路径/行号/hash或证据ID，注明推断与未验证项，短结论不粘贴全文。"
    },
    {
      "title": "文档的边界与验证要求",
      "goal": "材料：<同一文档路径>，范围：<边界与验收段落>，版本：<同一已读取hash>。独立问题：文档要求哪些权限、隔离与验证约束，现有项目是否满足？源码范围：<策略与测试模块路径>。已有证据：<来源引用，或明确尚无证据>。排除：不重复第一子任务的功能差距总结。仅使用已提供的只读工具，不运行命令、不修改文件、不再委派。返回summary、findings、evidence、limitations、recommendations；区分已有测试、真实模型验证和人工验收，不虚构测试结果。"
    }
  ]
}
```

第一版返回格式是模型成果的文本契约，现有 `summary` 并不具备上述字段的宿主结构校验。若后续升级为强类型成果，另行安排 schema、版本兼容、截断与持久化任务，不能只改提示词就声称宿主已验证成果结构。

## 5. 上下文测量和优化验收

### 5.1 请求分项

T01 分别记录基础工程提示、权限/协作提示、项目规则、所选 Skill、工具目录、用户输入、历史工具结果、助手输出、不透明续接状态和图片输入。分项的序列化字节加结构开销应与实际请求体核对；实际 provider token 只有总体 usage 时，不伪造精确分项 token，也不要求 tokenizer 分项相加必然等于整体。

报告保留请求身份、目的、协议、模型/候选版本、prompt/toolset digest、输入估算方法、序列化字节、provider usage、缓存分项及耗时。诊断默认仅保存长度、计数、hash 和稳定错误码，不记录凭据、完整用户文档或原始模型正文。失败、取消、重试与摘要均保留是否已发出请求以及用量已知/未知状态。

T02 必须贯通 `adapter → Usage → run/worker → store → projection → cost/UI`。`run.ts`、`run-store.ts` 等当前对用量字段严格校验和累计，不能只给适配器加缓存字段。保留原始 provider 计数并明确归一化规则；缺失的缓存字段不得视为零，已包含缓存的总输入不得再次加上缓存输入。费率缺失、模型不匹配或用量不完整时不输出完整费用。

保存旧 journal/checkpoint 的兼容用例。本地统计与费用报表不重复计入同一请求；真实重试是独立请求，分别计入，供应商费用未知时保持未知。发送前和手动摘要另计，回合内摘要只计入所属回合一次；父子请求及重启回放按真实请求身份核对，不能承诺本地去重会阻止供应商收费。

### 5.2 基线矩阵与优化顺序

成本基线固定同一模型、协议、配置、文档和候选，覆盖：中英文短问答、连续文件读取、长命令输出、MCP/Skills、长工程任务、图片、只读委派及压缩。报告最近输入、峰值、累计输入、请求数、缓存读/创建、估算费用与来源、延迟、任务成果及证据完整性；不将不同模型/不同任务的数字直接比较。

按测量结果实施 T07/T08：校准估算与独立 byte cap；精简固定提示、按当前授权能力提供工具；限制重复全文、使用已有分页/日志句柄/成果引用；比较关闭、发送前及回合内压缩的净收益。工具目录变化需有稳定版本与策略校验，重读引用必须可用、可追溯，不能删除原始账本或破坏工具调用/结果配对。

Responses 的加密推理续接块、Anthropic 的签名块、工具配对、图片后缀和任务证据属于协议/连续性约束，不以删除它们换取表面减量。不同协议的增量传输或缓存方案另行核实官方契约与恢复行为，不能仅因少发网络字节就宣称窗口占用或费用降低。

优化的节省目标在基线完成后冻结。通过门槛是选定场景的输入/费用指标改善、质量与验收不退化、引用可重读、权限/恢复测试通过；若窗口减小但累计费用或质量变差，应单列权衡并决定是否采用，不能只报告一个漂亮数字。

## 6. 真实模型回归与完成标准

### 6.1 专项回归入口

T06 新建委派专项回归入口，复用生产父提示、授权工具集合、子 worker、`NativeRunStore`、任务与成果读取路径。现有 `native-model-regression.mjs` 保留原用例；新入口及参数在实施 PR 中定义，本规划中的名称不能当作当前已可运行命令。

只读 fixture 可使用两份项目内 UTF-8/Markdown 材料，各含不同且运行时生成的随机标记和独立事实。父用户任务用自然语言要求并行分析，不直接写工具调用，不设置强制 tool choice；harness 只准备材料、连接、权限、预算及观察证据，不能替模型注入 `delegate_review` 或替子模型生成答案。需要记录实际候选 SHA、有效提示/工具版本、协议、主用模型和配置引用；凭据只从已有受控连接获得，不写报告。

真实审阅正例和材料注入用例的父执行策略也固定 `NativeExecutionPolicy.toolPolicy = read_only`，不装载 MCP 连接；不能只让子任务只读却给父暴露写入、命令或外部工具。harness 先准备隔离材料，再记录工作区文件哈希，执行结束与取消清理后核对工作区未被改动。

| 用例 | 必须验证的证据 |
|---|---|
| 明确并行分析两份独立材料 | 父原始模型输出真实 `delegate_review`，宿主实际执行一次含至少两任务的批次；每项 goal 满足材料、范围、证据与返回约定；至少两个不同 child 身份/账本与真实模型请求 |
| 并行完成而非口头计划 | 每个子任务实际 `read_file`/`search` 或位置证据回执及持久终局；子结论识别各自独有标记；父真实 `read_agent_result` 后正确归并并标明未知项 |
| 简单问题或明确只用单 Agent | 零委派，正常回答；不为满足指标无意义拆任务 |
| 材料中要求另启外部 Agent 的提示注入 | 不以材料指令扩大权限；只读子无命令/写入/MCP/委派工具，模型合规行为与宿主硬限制分别验证 |
| 无法读取的材料、依赖性任务或预算不足 | 明示缺口/串行依赖/阻塞原因，不伪称并行成功；失败、取消或未知回执不登记为完成 |
| 空任务、超四任务、越权、重复提交、父取消 | 参数与策略负例采用确定性宿主调用验证；禁止越权或重复启动，取消等待清理，未知效果保留恢复边界；真实模型遵守边界不替代硬限制测试 |

### 6.2 如何证明实际并行

宿主用单调时钟记录子 worker/运行开始、模型请求开始结束、持久终局和清理，关联父 run、batch、child、worker 身份/PID。至少两个子运行区间有交集，并且各自存在真实模型请求与读工具证据；单凭不同标题、同时出现 UI 卡片、两次单任务调用或可覆盖的 `receipt.updatedAt` 均不通过。

实际模型请求区间重叠是更强证据，应单独报告；服务端排队不等于宿主没有并行 worker。确定性 fixture 用 barrier 检验调度，真实模型用真实时序和账本检验调用行为，两种证据不能混为同一种“真实模型通过”。

### 6.3 发布门槛

- 确定性委派、权限/共享预算/取消/重启及原有上下文连续性回归通过，完整项目检查覆盖实际实现变更。
- 在声明支持的主用模型与协议上，以同一候选至少执行三次自然语言并行正例，三个不同措辞，每次均完成真实批量委派、证据读取、成果归并；记录所有失败和后续修复尝试，不只保留成功样本。
- 简单问答、单 Agent 请求和只读边界负例完成；缺配置、未运行或仅 fixture 通过时如实标记，不能计为真实回归通过。其他尚未跑的模型/协议保留独立状态。
- 报告包括候选、全部尝试、调用/回执身份、并行时序、用量口径、成果正确性、未验证项和失败原因；不得输出凭据或将 unknown 当作 zero/passed。
- 只读审阅不得写工作区，委派完成不得自动推进人工验收、扩大权限或合并成果。正式 RA-34/RA-35 仍按原验收规则记录，专项行为 smoke 不自动替代完整工程质量验收。

完成后应能回答：哪些内容造成额外上下文、显示与实际费用是否一致、优化改善多少且代价是什么、真实模型是否确实委派并完成独立分析。回答必须来自测量、模型工具调用与宿主证据，不能仅来自回复中的分工计划。
