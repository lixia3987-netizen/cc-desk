# Native 交互提问

本批补齐规划中的“批准、拒绝、提问”交互。Claude 仍为默认引擎。

Native 常驻工具 `ask_user` 接入现有问题卡片、注意力中心与 `waiting_input` 状态。一次可问 1–3 个问题，每题可给最多 8 个选项，也可不提供选项而直接接收文字；用户始终可以填写自己的回答。问题必须唯一，单题最多 1000 字符，单个回答最多 4000 字符，全部回答最多 16 KiB。

回答不会授予其他工具权限。后续写文件、命令或 MCP 调用继续使用各自的精确参数审批。

## 执行与记录

- 提问复用核心审批等待过程：等待用户的时间不计入执行时长预算，默认 5 分钟过期；取消会清除问题，过期、拒绝以及同一回合重复被拒绝的相同问题均有工具结果。
- 主进程校验问题 schema、当前运行身份、工具调用 ID、输入摘要、策略版本与到期时间。过期、其他问题、其他运行、缺失或多余回答均不能提交；回答不能包含当前模型或 MCP 连接的凭据。
- 回答先留在主进程内存中。核心持久化该调用的 `tool_prepared` 后，工具才返回回答，并由普通 `tool_completed` 进入模型上下文和账本。
- 刷新问题卡片不会重新发起问题。已完成提交的重试读取原回执；重启不会恢复为可交互的旧问题。如果准备记录已写入但结果未确认，沿用账本恢复隔离，不重放问题或猜测丢失的回答。
- 为兼容现有答案对象及多选展示，问题不能使用 `Object.prototype` 的属性名，多选选项标签不能包含 `, ` 分隔符。问题内容和选项是模型提供的文字，不是权限指令。
- Native 卡片不显示当前不支持的“审批说明”输入框；答案在对应回答框提交，Claude 的说明行为保持不变。

## 本地验证

`apps/desktop/tests/native-questions.test.ts` 使用本地 Responses HTTP/SSE fixture 和真实主进程执行器，覆盖正常问答、后续写入独立批准、非法或泄露凭据的回答、拒绝及重复问题、取消与过期、等待预算暂停、重启回执去重，以及写入准备记录后中断的恢复边界。

此验证不代表真实模型服务、Electron 图形界面或 Windows/macOS 打包验收；未触发 CI。
