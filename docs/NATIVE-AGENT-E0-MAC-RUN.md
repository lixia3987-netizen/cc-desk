## 不限预算与实际运行边界

用户已允许本轮不设额外操作者预算。应用与服务的固有边界仍需如实登记，本次不把默认值自动调到最大，也不声称模型具有无限上下文或无限输出。

Native 当前默认每回合 30 次模型请求、60 次工具调用、10 分钟主动时长；可配置上限为 100 / 200 / 30 分钟。默认上下文输入估算上限 64000 token、单次输出上限 8192 token；它们不是整轮累计 token 预算。审批等待排除，准备/启动/接纳耗时计入主动时长。正式记录使用实际会话配置，触及产品边界时如实记录结果，不自动重开回合规避。

现有 v1 操作者记录只接受有限数或 `null`，`null` 表示未知；不能用 `null`、0 或一个极大数冒充“不限”。本页作为明确的无限额授权与范围记录；各轮 `configurationReference` 指向的实际配置快照应引用本页，并在 `limitations` 披露表达限制。实际引擎/代理约束写入该配置快照，不用本页替代真实配置。v1 无法结构化表达不限的字段继续保留表达限制，报告比较不得忽略本页和实际配置。

因此 `engineering-readiness` 对相关字段仍可能报告 `missing_budget`；这里表示旧工具的表达能力不足，**不表示用户尚未授权预算**。该只读检查从来不是正式执行授权门禁，`executionAuthorized: false` 也不是对本次用户指令的否定。没有把 `metadata_complete` 作为运行结论；若未来扩展记录格式，须明确区分有限、不限与未知，并同步报告/对照/验收快照，不能只加一个放行开关。

1. 在 cc-switch 的“关于”、当前供应商和路由页面核对版本、Claude/Codex 两侧实际供应商、API 格式、地址及模型映射；保存脱敏截图或配置摘要。只提交这些元数据，密钥继续留在本机。
2. 确认 cc-desk 应用对应固定产品候选；在同一 Mac 上检查 Claude 的配置目录和会话模型覆盖，创建 Native 显式连接。代理/服务的实际重试、超时及自动切换策略也记录在配置引用中；发生自动切换须披露实际服务变化。
3. 在独立临时项目中，分别确认两个引擎的短文本、读文件、精确写入审批、短命令、取消及状态刷新。Native 的“测试连接”与这些任务会产生真实请求，计入本轮过程记录；不因连接成功就判工程能力通过。
4. 按 [E0-01](NATIVE-AGENT-E0.md#3-材料隔离与现场准备)创建 12 份独立任务副本；把独立验收器和参考 patch 留在评估者环境外侧，不交给模型。不要在日常工作目录执行注入或验收。
5. 在评估者仓库创建新的操作者记录目录，例如在 Mac 终端执行：

   ```sh
   node scripts/native-eval.mjs engineering-init "$HOME/cc-desk-e0-mac-20260929" 5980b06058b8e6d262df71562eeed7513c1202af
   node scripts/native-eval.mjs engineering-readiness "$HOME/cc-desk-e0-mac-20260929"
   ```

   初始化拒绝非空目录；上面的目录用于操作者记录，不是模型工作区。实际模型、协议和配置尚未登记时检查应阻塞，不能复制示例填成已验证。
6. 每轮使用新会话、相同任务指令和对应独立副本；完整保存成功、失败、取消、产品限额、代理异常及人工介入。若两边无法使用相同上游模型/路由，明确披露差异，不把它归因于引擎质量。
7. 使用既有 `engineering-verify / engineering-report / engineering-compare` 完成独立代码检查与汇总，具体命令见 [E0-02](NATIVE-AGENT-E0-REPORTS.md)。验收在不含用户/模型凭据的独立账号或隔离环境运行，实际图形及平台结论另行登记。
