## 本轮交付

### 中断后的显式恢复

主进程从原始账本重建恢复状态，展示已记录结果、未执行和结果未知的工具数量。用户先核查现场与旧进程，再选择“已核查，恢复会话”。

- 没有任何 prepared 未完成或 unknown 结果，且 Responses 协议可完整校验的会话，允许恢复。已有工具结果保留；只有从未进入 prepared 的调用才补充 `not_executed`。
- `recovery_resolved` 作为一个追加并 fsync 的原子事件收束旧回合，不执行工具。事件绑定原账本哈希；旧审批不会沿用。
- 已有终态回执原样保留；原先没有终态回执的中断提交形成取消回执。重复恢复不会追加结果或重新执行原请求。
- 任何 prepared 后无持久结果的工具（包括读取工具）均保守视为未知。核查确认只能解除目录隔离；旧会话仍只读，需要新建会话继续。
- 恢复不自动提交“继续”、不恢复队列或工作流。用户发送新指令后创建新回合，并重新检查文件版本、目录归属和当前项目指令。

### 手动上下文压缩

用户从运行预算面板选择“压缩上下文（可能计费）”。使用原服务与模型，在隔离 utilityProcess 中进行一次无工具摘要请求，不自动重试，不执行项目命令。

- 压缩完整旧回合前缀；逐字保留最初用户目标与最近一个完整回合。工具调用和结果必须成对保留或成对进入摘要范围。未知协议内容拒绝压缩。
- 摘要作为明确标注的 assistant 历史数据，不进入系统或项目指令。下一回合重新读取当前 AGENTS.md。旧 continuation 不沿用。
- 输入按实际摘要封装与固定指令的 UTF-8 字节先验检查；输出上限为会话设置与 4,096 tokens 中较小者，时长上限为会话设置与 60 秒中较小者，响应上限 256 KiB，摘要上限 32 KiB。
- 只接受完成、非空、无工具的纯文本摘要。新上下文必须严格更小；否则不替换上下文，但已发生的模型请求仍可能计费。
- 原始账本不删除、不重写。`context_compacted` 原子发布新上下文、摘要实际用量及压缩前后字节；记录通过 hash/seq 绑定源历史。缺失用量保持未知。
- 生成失败或取消不会替换原上下文。写入错误可能发生在 fsync 之后，此时关闭并重开原账本，以实际持久记录决定旧态或新态；不得把失败提示当作“必定未提交”的证据。
- 同一请求进行中共用 executor 操作；IPC 并发调用可以返回繁忙。已提交的最后一次压缩重试直接返回回执，重启后无需凭据、不重复调用模型。

### 执行互斥与显示

恢复和压缩与发送、会话配置、连接修改、目录管理共享执行屏障；压缩遵守最大并发会话数。队列明确暂停。停止与退出等待摘要 worker 实际释放；清理未确认时继续持有目录与恢复屏障。

退出同时封闭新的账本读取，等待已在途的记录加载完成并释放写入锁，避免正常退出留下未完成的锁文件。退出期间到达的界面读取使用已有投影；不删除或跳过异常锁校验。

界面恢复状态来自结构化 DTO，不再通过中文错误字符串判断。压缩后展示新预算估算与前后字节，清除不再对应当前上下文的旧输入用量。原始聊天与工具记录仍可查看、搜索和导出。

## 验证范围

新增账本回归覆盖：安全恢复、实际已完成操作不重放、未知读取/写入/命令阻断、旧回执保留、重复操作、版本冲突、协议配对、摘要权限、连续压缩、用量缺失、损坏及故障注入重启。

桌面定向回归使用本地真实 HTTP/SSE 服务，验证单请求、无工具、凭据反射拒绝、预算边界、超时、晚到响应取消、配置及删除互斥、重启后接续压缩上下文。正式 Electron E2E 新增四条恢复/压缩/取消/未知效果流程。

退出回归在写入锁创建途中暂停，验证退出等待、迟到读取不会新建账本，以及锁释放后原账本可重新打开。既有任务状态测试用显式握手保留暂停状态，避免依赖固定 100ms 的观察窗口。

固定最终提交的根检查、三平台源码 E2E 与成品启动结果记录在本轮 PR；不以 P4a 的绿灯替代。本地没有图形显示服务，Electron 图形验收由 CI 执行。

## 后续与限制

本轮交付 P4b 的显式恢复与手动压缩，不包括自动阈值触发、分块摘要、未知副作用自动重放或多协议恢复。历史前缀本身超出摘要输入预算时直接拒绝，需调整预算或新建会话；压缩不释放原始账本占用的磁盘空间。

摘要属于有损信息，不能保证保留全部约束。最初目标与最近回合原文保留，关键约束可由用户重新补充。真实远程服务、模型、凭据来源与验收预算尚未指定，本轮只调用本地 fixture；真实模型验收仍待执行。MCP、Skills 和更多协议继续放在 P4c。

新版本可以读取 P4a 的原始账本。执行恢复或压缩后会出现新增事件，旧版本无法识别这些事件，不能继续写入该会话；回退应用前应备份用户数据，并继续用支持 P4b 的版本打开已维护的会话。
