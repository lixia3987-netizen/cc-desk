# N3-02：回合内上下文维护

日期：2026-09-29（北京时间）。开发基线：`dev/native-agent@da74cc601d6fcecbd1e28aa619053c75510f8809`。本批在已有手动压缩和发送前自动压缩基础上，为长任务增加完整工具批次之间的上下文维护。正式运行由 [RA-27](NATIVE-AGENT-RUNTIME-ACCEPTANCE.md) 单独登记。

## 配置与触发

自动压缩仍默认关闭。原来的“发送前自动压缩”保持原语义；新增“发送前及回合内自动压缩”需要显式选择。达到本地输入或上下文字节预算的 90% 时检查是否可以压缩，本地估算不是服务端实际计费 token 数或模型窗口。

发送前最多尝试一次摘要，回合内最多尝试一次摘要，两者均占用同次提交的模型请求次数和运行时间预算。回合内必须为摘要后继续执行保留至少一个普通模型请求名额。摘要失败、不缩小或提交结果不确定时停止，不连续请求摘要。尚无可压缩历史等未发送摘要的检查可以在后续完整批次边界再次进行。

单次摘要仍受当前输入预算、剩余运行时间和输出预算约束：最长 60 秒，最多 4096 个输出 tokens，纯文本摘要最多 32 KiB。前置检查发现保留内容本身仍超预算、历史无法装入摘要请求或连续性引用超限时，不发出付费摘要请求。

## 安全边界与保留内容

压缩只发生在完整模型响应及其所有工具结果均持久保存之后，下一次普通模型请求之前；不在流式输出、审批、工具执行或一组调用/结果中间切断。既有工具调用 ID、拒绝审批记录、运行身份、任务身份和工具预算保持原值。

宿主保留原始用户目标、当前回合用户输入和最近完整模型/工具批次；旧历史由隔离的无工具摘要请求生成历史摘要。原始协议日志继续保存在账本内，不因压缩删除。供应商 continuation 不跨被替换的上下文继续使用，两种协议分别校验完整调用/结果配对。

任务计划、待办、条件和证据引用由宿主生成独立连续性记录，保留版本与未解决错误，不能靠模型摘要重新创造验证事实。日志正文和代码片段继续保留在原任务/运行记录中。连续性记录以 32 KiB UTF-8 为上限，不能容纳所需引用时明确停止，不静默删掉计划或证据。这些内容属于历史与状态数据，不授予执行权限；继续修改任务时仍需读取当前任务修订。

项目的 `AGENTS.md`、`CLAUDE.md` 和所选 Skills 沿用原指令与审批边界；摘要不能升级其中引用的文本为新的宿主指令。压缩期间指令变更会阻止该回合继续，不在同一回合偷偷更换策略。

## 与长命令及恢复的关系

本批延后对仍有 prepared/running/unknown 命令的回合进行压缩。命令终态确认后，可以在后续完整工具批次边界再次检查；不能为了压缩自动停止、重启或接管命令。若仍无法压缩而上下文超过硬预算，按既有预算终止与 N3-01 清理流程收束，不放宽预算。

宿主在摘要请求前持久保存尝试记录，成功摘要经校验后先持久保存新的上下文，再向运行 worker 确认切换。写盘失败、切换回执丢失、取消或重启不能把旧 worker 上下文覆盖回账本，也不自动重做未知请求。已提交的上下文是恢复依据，原始记录与未确定状态保留待核查。

回合内摘要请求的已知用量计入原回合；缺少服务端用量时保持未知，不伪造零费用。发送前/手动摘要继续按既有独立回执展示用量。状态面板区分正在回合内压缩、已提交、失败和未知；得到一段摘要文本本身不表示上下文已切换或任务已验收。

工作流阶段摘要只取同一回合最新原始模型响应中的实际文本；没有文本就保持为空，不把内部连续性记录或历史压缩摘要当成模型最终回复。重复读取已完成提交沿用相同规则，不启动新的模型请求。

旧日志以及既有手动/发送前压缩继续可读。新增回合内事件和配置值可能不被旧版本识别；回退前保留数据备份，不通过删改账本事件强行兼容。本批保持默认引擎、原配置模式和日志 schemaVersion 1，并新增三种宿主维护事件。
