## 1. 目标与交付边界

将现有“手动勾选项目 SKILL.md，每回合注入正文”补齐为可发现、可明确调用、可由模型选择、可按需加载、可管理、可追溯的技能系统。优先让用户现有技能可用，同时控制首轮上下文和界面等待。

本计划覆盖项目与用户来源、元数据、同名处理、调用入口、资源、脚本、安装更新、父子 Agent、持久化和性能。与现有文件/命令工具、审批、队列及工作流复用，不另建 Agent 执行框架。Claude 引擎继续使用自己的能力，Native 的技能配置不改写 Claude 的文件或设置。

格式基础参考 [Agent Skills specification](https://agentskills.io/specification) 和 [集成说明](https://agentskills.io/integrate-skills)，核查日期为 2026-10-17。采用“目录元数据、技能正文、辅助资源”三层加载；兼容范围逐项登记。Claude 特有 hooks、独立上下文/agent、动态命令展开、模型切换及所有客户端私有字段不列入首轮兼容承诺。插件市场、远程资源协议和云端技能同步另行规划；本计划包含本地及固定 Git 版本的导入管理。

## 2. 预期使用体验

| 场景 | 完成后的行为 |
| --- | --- |
| 已有会话打开、继续发送 | 原来勾选的技能继续固定加载，无 frontmatter 的旧文档仍可用；不突然扫描 HOME 或自动加载其他技能 |
| 新会话普通任务 | 先给模型可用技能的名称、描述和唯一引用；模型判断相关性，再调用工具加载正文；没有适用技能则直接处理任务 |
| 明确要求使用某个技能 | 输入框选择 `$名称` 芯片，或 `/skill` 菜单选择来源；宿主在首个模型请求前加载确切版本，不依赖模型猜测 |
| 同名技能 | 显示项目/用户来源；项目短名优先，同级冲突须选择限定来源；保留两个条目，不覆盖原文件 |
| 技能引用文档、模板或脚本 | 文档按需读取，模板按需复制到项目；脚本显示准确路径、版本、参数及工作目录，按现有命令权限执行 |
| 点击扫描、保存、调用、更新 | 点击后立即显示进行中/待发送；慢 IPC 期间输入和阅读仍可用；失败显示可操作原因，保留草稿和选择 |
| 用户想知道是否用了技能 | 展示“已安装、可供匹配、本轮已加载、已加入请求/响应确认、失败/结果未知”；历史展示当时版本，不冒充当前生效状态 |

## 3. 来源、格式与选择规则

### 3.1 注册来源与唯一身份

| 来源 | 默认行为 | 可执行的管理操作 |
| --- | --- | --- |
| 当前授权项目/worktree 的 `.agents/skills`、`.claude/skills` | 发现直接子目录；不递归扫描磁盘或读取父项目之外目录 | 读取、预览、启用/禁用、固定加载；文件仍归项目管理 |
| 项目内其他显式 `目录/SKILL.md` | 保留旧路径选择；新界面可注册为独立条目 | 同上，不因注册一个文件扩大整个目录树访问 |
| 应用管理的用户技能目录 | 使用宿主用户数据目录下独立 `native/skills`；默认目录为空 | 本地导入、安装、更新、回退、卸载 |
| 用户 `~/.agents/skills`、`~/.claude/skills` | 在设置中首次启用该来源后读取，不因升级自动扫描 | 读取、预览、停用来源；不原地更新或卸载外部文件 |
| 其他用户目录 | 用户明确注册根目录，默认关闭自动匹配 | 读取、预览、停用/移除注册 |

`skillId` 由逻辑项目身份或用户作用域、持久 `sourceId`、技能相对路径组成，不使用显示名作主键；正文变化只更新版本，不改变 ID。目录移动或根路径重新绑定要有新来源修订，不能把旧引用静默指向另一个包。用户根路径只由主进程解析，模型不能提交任意绝对路径。项目逻辑 ID 在子 worktree 内映射到该 worktree 的实际根，不复用父目录的读取能力。

不把“已发现”等同于“允许自动匹配”。已授权项目的常规只读加载复用现有准入，不增加逐文件确认弹窗；脚本、模板写入、外部访问仍走已有权限规则。

### 3.2 元数据兼容级别

| 字段/来源 | 处理方式 |
| --- | --- |
| `name`、`description` | 新规范包解析并校验；名称、描述及来源进入候选目录；描述缺失的条目不能自动匹配 |
| `license`、`compatibility`、字符串映射 `metadata` | 展示和诊断，保留已知元数据；环境要求不是自动安装依赖或调用网络的授权 |
| 实验性 `allowed-tools` | 首轮解析展示，但不转为预批准、不映射 Claude 工具字符串；UI 明示未作为执行策略。若后续实现，只能收窄宿主能力，不能扩大权限 |
| 未识别字段 | 保留受限原始元数据并提示“未支持”，不解释为 hooks、工具授权或执行配置 |
| 旧无 frontmatter 的已选 SKILL.md | 继续整份作为 legacy 指南固定加载；目录名显示，不要求先修改文件才能继续任务 |
| 新发现的无 frontmatter 文档 | 可预览、手动固定加载，标注 legacy；补齐元数据后才进入自动匹配 |
| 损坏 YAML、重复 key、非标 tag、过深结构/过量 alias | 新规范模式给出有界诊断并排除自动匹配；不猜测修复后执行，不影响其他来源的发现 |

解析器使用受限 YAML 数据模式，限制 frontmatter 字节、深度、字段数和 alias；不执行构造器或动态求值。新包严格校验标准字段，非关键格式差异可展示为警告；具体宽松规则在 SK-02 的 fixtures 中冻结。必须覆盖 BOM、CRLF、中文正文、空描述、分隔符缺失及嵌套恶意数据。

### 3.3 同名、禁用和默认值

1. 固定加载、消息显式调用均保存确切 ID；原有双目录同名且同时勾选的两项继续保留，不受短名覆盖规则影响。
2. 未限定短名先找当前项目，再找用户来源。某一作用域存在多个同名时显示限定名称，要求选择来源；不按扫描先后静默任选。模型目录使用唯一 ID 和来源标签，不存在短名误绑。
3. 生效过滤顺序为：宿主/引擎支持 → 来源可用且已启用 → 技能未被全局或当前会话显式禁用 → 本轮未排除 → 调用方式允许。禁止项不进入模型候选，显式调用返回可解释原因。禁用不能被会话 pin 或模型调用绕过。
4. 区分来源开关、技能开关、固定加载和自动匹配。旧会话保持 `legacy` 模式；新会话采用 `catalog` 模式，对已启用来源自动匹配。外部用户根仍需首次启用。全局默认变更只按现有默认/自定义策略应用到后续回合，运行中不热切换。
5. 新版会话的自动匹配可关闭，关闭后仍可手动调用和固定加载。不增加每次模型选技能都要确认的弹窗；用户在设置中控制候选范围。

## 4. 架构与契约

按 `contracts → agent-node → Native host/worker → IPC → renderer` 分层。解析和受限资源读放在 agent-node；应用来源配置、运行所有权和安装管理留在 desktop main；agent-core 只承载必要的通用运行事件/连续性约束，不引入 HOME 或 Electron 依赖。

### 4.1 核心对象（拟议）

| 对象 | 关键字段及用途 |
| --- | --- |
| `SkillSource` | `sourceId/scope/kind/enabled/revision`；根目录映射只留宿主，不接受模型改写 |
| `SkillDescriptor` | `skillId/sourceId/relativePath/name/description/metadataHash/sourceFingerprint/status/diagnostics`；必须绑定文件与父目录身份、大小及高精度变更时间，不在发现阶段要求读取全部正文 |
| `SkillCatalogSnapshot` | `catalogId/revision/orderedDescriptors/digest/truncated`；绑定会话、项目和有效过滤配置 |
| `SkillVersionSnapshot` | `skillId/sourceRevision/fullFileHash/bodyHash/bytes/format` 及不可变正文引用；激活时完整读取后生成 |
| `SkillActivation` | `runId/skillId/version/origin/requestId/receiptSeq/activationRevision/offeredToRequestId/confirmedByResponseId`；区分加入请求与完整响应确认；origin 为 legacy、pinned、explicit 或 model |
| `SkillResourceReceipt` | `skillId/version/relativePath/contentHash/bytes/operation`；引用被读/复制/执行的确切资源 |
| `NativeSkillSubmission` | `schemaVersion/explicitSkillRefs/excludedSkillIds`；引用含 ID、来源修订及选择时版本；进入提交摘要和队列持久化 |

候选目录的 hash 不能冒充正文 hash。扫描只读取受限头部并固定 sourceFingerprint；显式选择时或激活时才读取完整文件并绑定版本，加载前后核验身份与指纹。无法提供可靠变化判据的来源须预先冻结完整版本或要求刷新，不能仅比较 frontmatter 后宣称正文未变。索引缓存对展示有效，不用于跳过执行前的真实身份与内容核查。

### 4.2 拟议工具与 API

| 入口 | 职责与限制 |
| --- | --- |
| `list_skills({query?, cursor?, limit?})` | 查询本轮冻结的已启用目录；有界分页，返回唯一 ID、描述、来源和版本提示，不读取正文 |
| `load_skill({skillId, catalogRevision})` | 校验属于本轮目录、当前来源身份及内容；提交完整正文工具结果及激活回执；重复同 ID/版本不重复注入 |
| `list_skill_resources({skillId, path?, cursor?})` | 已加载技能根内的有界元数据列表；不扫描 HOME，不沿链接跨根 |
| `read_skill_resource({skillId, path, cursor?, maxBytes?})` | 读取已加载技能中的文本资源；返回真实 hash/完整性/续页标识；二进制返回元数据及受支持操作说明 |
| `copy_skill_asset({skillId, path, destination, expectedHash})` | 资源模板复制到项目，复用写入预览和审批，不开放任意宿主目标路径 |
| `start_skill_script({skillId, path, argv, cwd, timeoutMs?})` | 以技能版本快照准备命令，复用 start/status/output/stop 生命周期、权限与回执；只读 Agent 不提供此工具 |
| `nativeSkills` IPC | 扩展 catalog、inspect、refresh、来源/选择保存、安装预览及实际运行状态；根路径只能通过可信设置入口注册 |

资源、脚本接口可在后续 PR 注册；无合格来源时不发送空目录和无用工具。工具名在 SK-01 冻结后再成为公开契约。所有新增 IPC 具有严格输入、会话身份、项目/worktree 代次和迟到结果校验。

### 4.3 显式调用与持久队列

输入框以技能芯片为权威，`$名称` 自动补全和 `/skill` 菜单为选择入口。限定来源选择解析成 ID；正文代码块、引用、文件内容、货币符号和 Shell 变量中的 `$name` 不触发。首版不实现任意位置纯字符串替换；用户明确输入调用格式时，发送前转换为可见芯片并完成歧义检查。

扩展 contracts/chat、ChatSendOptions、QueuedChatMessage、chat handlers、queue storage、执行端参数及 NativeRunStore 配置。技能引用与 text、attachments 一起参与 `clientRequestId` 的去重摘要。同一 ID 不同技能选择必须拒绝；已受理提交重试返回原回执，不重新读取新版本或再次执行。Claude/Shell 拒绝不适用的 Native 技能字段，不静默吞掉。

消息级引用在接收提交时解析并冻结版本，排队期间更新来源不改变原提交。实际执行前再检查来源可用性和版本；变化时暂停该消息，展示差异，允许用户重新选择后以新提交身份发送，不能自动替换版本。消息接受之前失败保留草稿；接受之后失败保留队列和回执，沿用现有去重展示。

## 5. 激活、审批与连续性

### 5.1 渐进加载与真正生效

首个请求包含有界候选目录以及 legacy/pinned/本消息 explicit 正文。自动匹配由当前任务模型根据描述判断并调用 `load_skill`；不另开分类模型、不用关键词强制所有任务加载技能，也不承诺模型每次都判断正确。

激活顺序为：校验来源 → 检查正文和输入预算 → 完整读取 → 准备可追溯结果 → 持久化成功回执 → 加入活跃版本 → 提供给下一次模型请求。记录 offeredToRequestId，只有该请求产生完整且已持久化的模型响应后才记录 confirmedByResponseId 并解除副作用屏障；网关错误、断流或取消保持未确认。它证明正文进入了完成响应所对应的请求，不证明模型理解或遵循正文。任何写盘失败、正文截断、取消或版本变化均不得标记成功。通用工具输出截断器需要为技能完整正文提供专门预算检查，不能先截断再报告“已启用”。

同一模型响应同时输出 `load_skill` 和写入/命令时，新正文没有进入生成该响应的请求；新激活后的副作用工具返回明确的未执行原因，待包含该正文的后续请求完成并持久化模型响应后重新准备。已执行的旧操作不回滚、不重做；只读查询可继续。测试以实际模型请求和完整响应回执证明此行为，不能只按工具执行先后猜测。

### 5.2 审批与并发中的变更

旧固定技能继续参与 ProjectInstructions.digest。新模式维护独立 ActiveSkillSet；本地文件、变更集、命令、MCP、提问答复及委派准备中的策略摘要共同绑定：适用项目规则摘要、活跃技能版本、激活修订、宿主权限及运行身份。所有 prepare/validate/execute、worker RPC 与相关审批卡片统一检查，避免只保护 apply_patch。

新增激活只能在完整工具结果边界生效；存在待确认操作、未核查副作用或仍运行的命令时先拒绝/延后激活，不热替换正在执行的程序，也不因为目录刷新中止已确认提交。正文或已引用资源变化使尚未执行的旧批准失效，保留可检查原因；已经成功提交的操作继续按原回执确认。

格式字段不授予访问凭据、网络、命令、MCP 或递归委派的能力。脚本仍可拥有用户已批准命令所具有的系统访问范围，不能把包根限制称为操作系统沙箱。

### 5.3 持久化、压缩、重启与子 Agent

- 活跃技能清单及正文快照采用内容寻址的不可变引用，并关联真实激活回执；缓存或 renderer 状态不作为执行依据。先使用兼容的现有持久回执结构承载元数据；若确需新增 journal 事件，必须同时更新严格 schema、worker、回放和旧版本行为。
- 压缩后的 continuity 保留完整活跃约束和来源版本，正文不交给摘要模型任意概括；其字节继续计入输入预算。移除并重新加入正文时重建请求/响应确认状态，不能只有激活标签。若完整约束已超输入预算，明确阻塞，不静默丢弃。
- 应用重启可以还原历史使用版本和中断状态；本计划不增加 Native 原生 resume，也不自动继续未知副作用。下一新回合重新读取固定技能及当前目录，旧历史保持旧版本。
- 子 Agent 继承父目录/固定技能/任务相关已激活技能的版本清单和过滤配置，不复制父全部聊天。子运行仍独立记录激活、用量和结果；只读子可 list/load/read，不可复制模板或执行脚本。子可以从继承候选中加载其他相关技能，不扩大其工具权限。
- 项目技能在实现子 worktree 内重新绑定相对根并核对预期 hash；缺失或不一致时该子任务返回来源差异，不能偷读父工作区、静默使用旧内容或影响主任务继续。用户全局版本引用可共享不可变正文，但资源能力仍绑定各自运行身份。
- `recover_agent` 保持新身份、新上下文、新独立预算；保留旧证据，重新建立本次来源快照并标出版本变化。原脚本/工具回执不重放，未知清理或现场仍按现有恢复屏障处理。
- 主 Agent 无请求/工具/时长总限额；子 Agent 继续各自默认 30 分钟、60 次请求、120 次工具调用，可配置至 300 分钟、200 次、400 次。加载工具计入调用者自身工具计数；不新增父子共享 Skills 执行时长预算。终局子任务释放并发额度，失败隔离和自动恢复语义保持。

## 6. 辅助资源、脚本和安装管理

资源相对路径统一以技能根解析，与项目工作目录分开。复用 ProjectFiles 的普通文件、句柄、目录身份、取消及敏感路径校验，增加注册用户根的受限实现；拒绝 `..`、绝对路径、URL/include 自动导入、符号链接及 Windows junction 逃逸。技能引用另一个技能时必须重新按 ID 激活，不能通过相邻目录读取绕过候选过滤。

文本资源支持分页；不能把截断页当全文。模板复制显示目标 diff、来源版本和覆盖条件，走现有写入生命周期。图片/二进制仅在已有模型附件与预览能力支持时接入，不把任意二进制转换成隐式模型输入。

脚本执行分两步：准备时校验所需资源并物化有界、不可由模型编辑的运行版本包；审批绑定包清单/脚本 hash、解释器、字面 argv、项目 cwd 和输出/超时限制；执行前再核验快照身份，之后复用 NativeCommandTools 与 ProcessSupervisor。保留技能内相对资源布局，绝不拼接 shell 字符串或在读取 SKILL.md 时自动执行代码。依赖缺失返回明确诊断，不自动 npm/pip 安装、不运行包 hooks。可执行能力仍受现有权限模式影响，不另建逐技能授权弹窗。

管理功能先交付本地文件夹导入，再提供 Git 固定 commit 导入及更新预览。Git 获取不运行 hooks、submodules、LFS 过滤器或依赖安装；记录远端、固定 commit、包清单与内容 hash。导入目录逐文件限量校验、拒绝越界链接，临时目录完成后原子切换；失败/取消清理临时内容，旧版本继续可用。第一版不支持任意压缩包和自动定时更新。

更新展示元数据、正文及脚本变更，点击应用后仅影响后续新回合；有活动引用时保留旧版本，不在运行中改路径。回退通过已保存版本完成。卸载只移除应用管理包，不能删除项目文件或用户外部目录；外部来源仅停用或移除注册。

快照先完整写入、同步并原子发布，再在队列接收或激活回执的持久提交中建立版本引用；提交失败留下的孤立快照由后续清理回收，绝不先确认消息后补写正文。无需假定文件系统和队列拥有跨文件事务。重启后从权威队列、账本、子任务恢复证据及保留版本清单重建引用；扫描不完整、状态未知或写入尚未确认时禁止回收相关对象。队列移除只解除其队列引用，已启动/历史运行仍独立持有引用；运行结束不等于历史引用释放。历史删除、明确配置的内容保留期限到期及恢复证据删除后才解除相应引用，再在宽限期后回收无引用快照。默认保留仍可查看历史所需的版本，容量达到可配置上限时先清无引用内容，仍不足则给出容量错误，不静默删除有引用正文。SK-10/19 冻结容量与宽限期，并覆盖各持久化边界崩溃注入。

## 9. 性能、容量与失败行为

以下为首轮默认设计值，SK-19 测量后可调整并记录理由；字节限制独立于模型 token 限制。它们是本地容量边界，不是主/子 Agent 共享执行预算。

| 项目 | 建议初值与验收方式 |
| --- | --- |
| 来源和扫描 | 最多 16 个注册根，每根直接子项最多 256、总候选最多 512；并行磁盘读取最多 4；自定义技能单独登记，不递归搜索整盘；超限提供准确诊断 |
| 元数据 | 单文件头部扫描最多 8 KiB；初始模型目录最多 64 条且最多 16 KiB，完整描述装不下则减少条目；其余可 list_skills 分页/查询，不能静默截断描述 |
| 正文 | 沿用单文件 32 KiB；legacy/pinned/explicit/model 活跃技能去重后合计最多 16 项；与适用 AGENTS/CLAUDE 正文共享 128 KiB，另受当前模型输入余量约束 |
| 资源 | 文本每页默认 16 KiB、最大 32 KiB；列表每页 64 项；同时有操作时间/条目边界；模板/脚本包容量在 SK-13/15 基于 fixtures 冻结，不能无限复制整个目录 |
| 缓存 | 每来源元数据索引有界，总内存目标不超过 8 MiB；watcher 只标脏并去抖，显式刷新/每回合确认补充失效；网络盘失败独立呈现，不阻塞其他来源 |
| 界面反馈 | 下一绘制给出 pending，常规本机点击到反馈目标 ≤100ms；技能详情、历史正文和资源列表按需加载，不阻塞会话首屏 |
| 性能基线 | 固定 200 个标准技能，每正文约 16 KiB；本地 SSD 冷目录目标 p95≤500ms、热目录目标 p95≤50ms；记录硬件/OS/次数/字节，未实测前不宣称达标 |

目录或非关键来源扫描失败：其余可用条目照常展示，错误来源排除自动匹配。显式/固定选择失败：该消息明确暂停，不能静默忽略用户指定技能。自动 load 失败：返回无副作用错误，由模型说明缺口或使用其他已允许方法，不伪称遵循该技能。预算超限：加载前拒绝，无截断、无半激活；用户可减少固定项或使用更大上下文。

源文件在本轮中改变：尚未激活条目不从新版本悄悄加载；活跃技能继续保留旧历史快照，涉及后续执行的版本复核按第 5 节处理。目录刷新不重新发送消息、安装操作不自动启动模型、技能错误不改写整个队列的已提交成功状态。

| 审批变更 | 加载、正文/资源变化、权限变化导致未执行旧批准失效；覆盖文件、变更集、命令、MCP、提问和委派 | desktop 集成 |
| 压缩与重启 | 完整约束、版本、工具配对不丢；历史不漂移；未知副作用保持恢复状态 | store/continuity/worker |
| 父子与恢复 | 只读子能加载；实现子根不指向父；版本差异只失败该子；独立预算/并发释放保持；恢复不重放 | delegation + GUI |
| 资源与脚本 | 正确相对根、分页、链接/路径竞态、资产覆盖、审批包 hash、取消/超时/孤儿进程关闭 | node/desktop/Windows |
| 安装/更新/卸载 | 原子结果、固定 commit、无隐式代码执行、活动引用保留、外部目录不删除、失败回退 | store/IPC/GUI |
| 即时反馈 | 人为阻塞 IPC 时 pending 已绘制、双击只提交一次、失败保留草稿、切换会话无迟到覆盖 | Electron GUI |
| 长会话与性能 | 重开历史不扫描全局正文；目录、正文、资源开销分列；大目录和缓存压力不冻 UI | benchmark + Electron GUI |

真实模型专项使用隔离 fixtures 和随机标记：自然语言任务触发模型自主加载、读取引用资源，输出只有实际读取才能取得的事实；harness 不强塞 load_skill 或伪造子调用。至少覆盖当前三种模型协议（Responses、Chat Completions、Anthropic Messages）的受控机制回归；真实服务仅对实际指定连接/模型做报告，不把一种服务的成功推广为全部兼容。记录候选 SHA、格式/提示版本、目录/正文/资源字节、真实请求与用量来源、成功/失败/取消尝试。

本地每个实现 PR 运行受影响包构建、类型检查及必要定向回归；触及公共 contracts/运行/存储时完成相应广泛回归。Windows 实际 GUI 重点验证队列、反馈、父子、路径和进程，正式成品同时覆盖 macOS/Linux 目录与打包行为。没有图形环境时只能记录未执行，测试收集不能代替通过。本规划文档不占用构建和模型验收预算。
