# N3-03：错误诊断与有限恢复

日期：2026-09-29（北京时间）。开发基线：`dev/native-agent@152dd26470c4e402b519943428037ff7e47b21c7`。本批补齐失败请求的耐久记录、分类诊断、显式选择的有限模型重试与重复工具批次阻塞。正式运行由 [RA-28](NATIVE-AGENT-RUNTIME-ACCEPTANCE.md#ra-28n3-03-错误诊断与有限恢复) 单独登记。

## 配置和恢复范围

Native 会话新增 `modelRetry`，默认 `off`，启用 `safe_transient` 才允许有限重试。Claude 仍是默认引擎，不自动改动已有会话。

| 失败类型 | 自动重试 |
| --- | --- |
| 实际 HTTP 429、502、503、504 拒绝，成功响应流未开始，且没有已投影片段 | 可进入有限重试检查 |
| 认证/权限、连接/请求配置、其他服务错误、协议错误 | 停止并说明检查方向 |
| 网络错误、超时、断流、部分响应、无法确认原因的异常 | 停止；远端处理或费用可能未知 |
| 本地工具、审批拒绝、摘要请求、写盘失败或未知副作用 | 不自动重试 |

整个回合最多增加两次模型请求，分别退避 500 / 1500 毫秒；不是每个失败请求都另获两次额度。等待可取消，等待耗时和每次尝试均计入原回合预算。剩余请求额度或执行时间不足时停止。重试使用同一份完整上下文，不重复之前的工具、审批或命令启动，不重新发送被丢弃的流片段。

候选重试资格由协议适配器识别真实 HTTP 拒绝赋予，不能只靠异常消息或手工构造相同异常对象获得。两协议都不读取远端错误正文来生成诊断，诊断仅保存有限分类、HTTP 状态、是否出现片段和计划退避时间；密钥、远端错误正文、响应头及任意异常消息不进入这些字段。每次请求可能计费；重试并非免费恢复。暂不实现服务特定 `Retry-After`、供应商幂等键、参数降级或切换协议/模型。

## 日志、预算与恢复

普通请求在网络调用之前保存 `model_request_started`，失败保存 `model_request_failed`，完整成功响应仍使用 `model_response`。普通尝试序号独立于摘要次数，回合总请求数包含两者。任一失败请求的服务用量未知时，整回合合计用量和完整费用保持未知，不用成功请求的部分用量补成总账单。

日志一次只允许一个未闭合模型尝试；完整工具批次之后才能开始下一次请求。失败后只能按已保存的有限重试决定发起后续请求；未经新的完整成功响应，不能把失败直接收束为成功或进行回合内压缩。写盘确认不明直接进入恢复隔离，不自动重复网络请求，也不恢复旧工具副作用。明确恢复只收束原回合，后续需用户发送新指令。

开始记录会预留失败/成功结果及终局记录空间。失败请求的序号和未知用量在重新打开日志后仍可核对；旧版仅有响应的日志继续可读。新增事件保留日志 schemaVersion 1，旧应用未必识别；回退前应保留数据副本，不删改账本事件强行兼容。

worker 宿主另行校验事件顺序、请求数、响应归属、已观察片段、配置、退避时间及最多两次额外请求；并发或伪造事件不能绕过这些检查。未完成的临时文本在失败后清除，界面使用持久诊断显示原因，不把它变成完整助手消息或工作流摘要。界面区分计划重试和实际已开始的重试次数，取消等待不算已执行一次重试。

## 重复失败与无进展

连续三个完整工具批次的工具名、规范化输入和完整结果均相同，且都失败/被拒绝，或都为成功的只读操作时，停止继续请求并显示解释。成功副作用、批次或结果变化会重置连续计数。命令状态和日志轮询排除在只读无进展判断之外，以免把等待后台命令误判为停滞；仍受既有命令与回合预算约束。

这是一项针对明确重复的有限检查，不宣称能判断所有工程任务是否有实际进展。任务验收仍依赖已保存的验证证据和人工判断。已准备但结果未知的操作沿用原恢复隔离，不能为通过无进展检查自动重放。

阻塞说明给出稳定错误类别、已计入的请求/工具次数、实际重试次数及后续方向：检查连接或配额、核查工具与任务证据、调整预算或目标后发送新指令。它不自动批准后续操作，也不把模型回合结束改成目标已验收。

## 与 N3-01 / N3-02 的关系

长命令仍由宿主持有并在终局前完成清理；失败模型请求不会重启旧句柄或重复启动命令。回合内压缩仍只在已确认的完整批次边界执行，活动或未知长命令暂缓压缩。摘要请求不使用本批自动重试；已发起的摘要尝试也占用请求预算，普通请求曾失败时整回合费用仍未知。
