## 1. 执行与登记规则

1. 固定应用 commit / tree、任务基线、OS / 架构和实际包 SHA-256；运行中不换候选。同树的不同提交应明确映射，不能仅凭分支名登记结果。
2. 使用独立测试项目、独立应用数据目录及可丢弃的验收账号/数据；保留原有测试、项目指令和用户修改。故障场景仅作用于验收现场，不删除账本或放宽断言来获得通过。
3. 实际调用前记录服务商、API 基地址的脱敏标识、准确模型 ID、协议、凭据来源类型/变量名、单次及整批预算、审批方式和停止条件。凭据值、Authorization、远端 session ID 不进入报告、截图或仓库；预算估算不能替代服务端账单上限。
4. 每项记录北京时间、操作者、完整命令/步骤、退出码、原始日志/trace/截图的引用和结论。记录失败、取消、平台跳过和环境阻塞，不能只保留成功重跑；修复后新建候选记录，保留旧结果。
5. 状态使用 `pending` / `running` / `passed` / `failed` / `blocked`；不适用须写明原因并经人工确认，不能把不适用算作通过。真实质量结论还需人工审阅实际差异与覆盖范围。
6. 环境不支持某个故障或服务不提供某个回执时，记 `blocked` 或明确未覆盖，不伪造异常/用量。受控故障回归可以补充证明宿主边界，但不等同真实服务行为。

通用证据包 `R`：上述候选与环境信息、无密钥配置摘要、步骤/命令及退出码、会话/任务/运行标识、实际 diff、必要日志或 trace 引用、人工结论及未覆盖范围。以下“证据”列是除 `R` 之外的必要内容。同一次运行可覆盖多个 ID，但每个 ID 单独判断，不重复统计运行次数。

## 3. 真实连接、模型与编码流程

### RA-01：固定验收现场

- 前置/步骤：确定本次选用的正式 ID 和环境；从仓库根记录 `git rev-parse HEAD`、`git rev-parse HEAD^{tree}`、`git status --short`、`node --version` 与 `npm --version`。需要包时另记录构建机、实际产物及 SHA-256；保存不含凭据的配置。真实调用条件按第 1 节落实，CI/构建单独按用户指令执行。
- 预期：应用、任务与检查器候选可追溯，原测试/指令未变；默认引擎仍为 Claude，验收配置不影响原项目。
- 证据：`R`、选定 ID、模型/整批预算与停止条件、构建/CI 的主动执行指令引用。状态：**pending**。

### RA-02 / RA-03：两种模型协议分别验收

- 前置/步骤：分别使用用户选定的 Responses 或 Chat Completions 服务/模型新建 Native 会话。主动诊断后，完成“读取含中文/空格路径的文件 → 修改 → 批准命令验证 → 查看实际结果”；发送一个依赖前文的后续回合，干净退出并重启后再继续。另在安全文本请求中停止一次，核查服务错误/不支持参数时的明确报错。两协议分别执行，不能用一条路径推断另一条通过。
- 预期：文本与工具参数完整接收后才执行；逐次审批、真实文件/退出码、服务回执与 UI 一致；原生协议上下文可继续；不自动切换协议、模型或引擎。Chat Completions 所选服务须接受当前标准参数与流式结束方式，未支持 reasoning 等扩展明确失败，不能静默丢字段。
- 证据：`R`、服务与协议版本资料来源、脱敏请求/响应关联标识、工具调用/审批次数、前后文件、后续/重启会话记录。分别登记 **RA-02 pending**、**RA-03 pending**。

### RA-04：连接诊断与实际凭据后端

- 前置/步骤：在各目标 OS 的正常用户桌面环境分别验证环境变量、仅内存和系统安全存储；使用专用验收凭据。打开/保存/刷新设置应无模型调用；主动“测试连接”才发起一次请求，检查成功、认证错误及取消。重启检查内存凭据需重新输入、环境变量来自启动应用的环境、加密凭据可用；安全后端不可用时检查明确拒绝持久保存。
- 预期：活动连接不可被修改；就绪不等于已连通；已保存密钥不回显，不进入普通 workspace、历史、导出、诊断和工具环境。macOS 正式项必须使用实际 Keychain，不能沿用 `--use-mock-keychain` 的成品测试结果；Linux 不以 `basic_text` 作为安全存储通过。
- 证据：`R`、后端名称与实际系统提示、重启结果、服务请求计数、脱敏检查记录；不得把真实密钥打印到搜索日志。状态：**pending**。

### RA-05：实际用量、费用与预算

- 前置/步骤：为准确模型名录入显式价格，运行一次成功任务并对照实际用量；修改价格后重看旧回合并运行新回合。将请求次数/输出/主动时长预算设为小且有效的值，检查达到限制和审批等待。对服务实际出现的缺失用量、后续请求失败或模型名不匹配单独记录；服务无法产生这些场景时保留该子项未覆盖，并引用本地故障回归。
- 预期：历史价格快照不被改写；预算估算、服务实测用量与费用分开；部分/缺失用量不估算整回合总费用。压缩、缓存差价和附加费用不混作已计算总账单；预算停止不丢历史或自动重试。用量不完整不自动否定完整的功能证据。
- 证据：`R`、脱敏服务用量/账单引用、前后价格配置、预算停止原因、费用未知项。状态：**pending**。

### RA-06：正式审批与用户提问

- 前置/步骤：让真实模型先 `ask_user` 澄清再修改文件和执行命令；分别回答选项/自由文本、拒绝一次操作、在等待时停止。保留一个待批准编辑，外部修改目标或适用指令/所选 Skill 后尝试原批准；提问等待期间同样修改来源后尝试旧回答。需要过期场景时使用独立验收回合等待实际到期。
- 预期：回答不是工具授权；每次写/命令/MCP 仍单独审批。刷新不再发问题，过期/取消/来源变化后的旧批准与回答无效，不进入新的运行；原目标不被陈旧操作覆盖。模型不能通过计划更新授予权限。
- 证据：`R`、问题/权限卡片与注意力状态截图、拒绝/停止/失效的调用标识、目标前后 hash、服务调用记录。状态：**pending**。

### RA-07：AGENTS.md、CLAUDE.md 与 Skills

- 前置/步骤：在独立项目放置根及嵌套的双指令，设置可核查的冲突规则，并给一条明确用户覆盖指令。建立 `.agents/skills/<名称>/SKILL.md`、`.claude/skills/<名称>/SKILL.md` 和一个自定义项目相对 `目录/SKILL.md`。先预览来源，确认默认不选，再仅选指定条目完成局部重构；新回合修改来源、删除选中项并重启检查。平台链接/junction、中文路径的拒绝/可读行为与 RA-16 合并执行。
- 预期：深层优先、同层 AGENTS 优先、明确用户指令优先；未选 Skill 不加载，保存/预览不调用模型，不执行 frontmatter/hooks/include。来源变化使受影响审批失效；缺失/越界/超限不静默忽略。真实模型是否遵守内容须由实际 diff 判断。
- 证据：`R`、全部验收指令/Skill 内容及 hash、来源预览、选择记录、模型任务 diff；来源版本不混用。状态：**pending**。

### RA-08：真实模型压缩与连续上下文

- 前置/步骤：对 RA-02、RA-03 各准备至少两个完整回合及可压缩旧内容；主动手动压缩一次，再明确启用发送前自动压缩并达到本地阈值后发送。检查压缩前后的用户目标、最新回合、项目规则和 N1 任务索引；在独立回合取消摘要，再重启观察队列和重试行为。服务摘要无法缩小时保留失败记录。
- 预期：无工具摘要只调用一次，原始记录保留；取消/失败不伪装成功，不自动重做工具或反复付费压缩。自动摘要计入当次请求/时长预算，失败保留消息且队列暂停；用户显式处理后才能继续。新任务重新读取当前双指令/Skills，`read_task` 可取持久计划；不承诺有损摘要无信息损失。
- 证据：`R`、前后字节/摘要用量、服务请求次数、取消/重启记录、任务目标与约束的人工核对。状态：**pending**。

### RA-09：恢复、未知结果与提交去重

- 前置/步骤：在可丢弃现场分别于审批前、已批准操作进行中中断应用/worker；用实际文件或受控外部计数确认哪些操作发生。重启检查已记录/未执行/未知工具。安全中断核查后显式恢复并发送新指令；未知结果则人工核查后解除隔离、另建会话。利用既有 fault/E2E 入口验证同一提交回执重取，不手工篡改账本制造成功。
- 预期：旧审批无效；未知副作用不自动重放，不把客户端停止当作远端未执行。恢复/重启不自动继续队列或工作流；已经完成的提交只返回原回执。目录只有在对应资源和外层所有权收束后才释放。
- 证据：`R`、中断时间与账本状态、实际副作用计数、进程/远端现场核查、恢复前后审批与队列截图。状态：**pending**。
