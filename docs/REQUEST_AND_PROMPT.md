## 本次重建的开发提示词

实现一个本地优先的独立桌面客户端，封装用户已经安装并登录的 Claude Code CLI。面向 Windows PowerShell，同时兼容 macOS/Linux Bash 或 Zsh。不要要求 Claude Desktop。

使用 Electron、React、TypeScript，采用 node-pty 和 xterm.js 承载真实 CLI 交互。保持登录、权限审批、MCP、斜杠命令在 CLI 内原生工作，不模拟模型回复，不绕过权限，不复制认证数据。

必须实现：

1. 中文工作台、原生目录选择、项目分组、会话搜索、多会话切换。
2. 会话 UUID、创建/启动/停止/中断/重命名/归档/恢复，以及本地持久化。
3. 支持 Shell 与 Claude 两种会话；并发限制；真实 PTY 生命周期与窗口尺寸更新。
4. 调用本机 --version/--help 检测能力，生成类型化参数数组；不拼接 Shell 命令。
5. 模型与 effort 设置；只有 CLI 声明支持时提供选项，max 与 ultracode 不互相冒充。
6. 只读历史扫描与 UUID 导入；官方 --resume/--fork-session 方式恢复和分支。
7. 可选 Git worktree，检查 HEAD 后创建独立目录和分支；归档不删除代码或对话。
8. Git 状态、终端日志导出、长提示词编辑器与开发/审查/修复模板。
9. renderer 不具备 Node 权限；主进程校验 IPC 来源、参数与会话标识。
10. 状态原子落盘、备份、损坏保护、有界终端缓冲、进程树退出及应用退出确认。
11. 实际测试存储、参数安全、恢复、并发、Unicode 路径、PTY、worktree；再运行桌面操作测试。
12. 提供源代码、Windows 打包配置、Bash/PowerShell 启动脚本、使用说明和真实验证限制。

不要把静态页面、假数据界面或者仅有项目规划作为完成结果。若环境无法运行目标平台构建或真实登录链路，应交付可运行源码和可生成的产物，并准确注明哪些验证尚未完成。

## 实现范围

当前是基于真实终端的 v0.1 客户端，工作流以可编辑提示词形式提供。没有自建 Claude 模型服务，没有为未公开 Desktop 功能制作仿真开关，没有宣称实现官方 ultracode 的内部编排。

后续如需要完全结构化聊天界面、每次工具调用独立审批卡片、托管多 Agent 编排、WSL 发行版管理，可以在现有 Runtime 边界增加新适配器。本次不把这些列为已经实现的能力。
