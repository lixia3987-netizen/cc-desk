# Native 工作流阶段验收与成果记录

现有顺序工作流继续绑定同一会话、执行器与工作目录。阶段运行成功、任务验收和整个工作流完成分别记录；原有队列 `success` 与已执行消息确认语义保持不变。

本文的当前行为说明已更新至 2026-10-16 的独立子 Agent 预算策略；已发布安装包以对应版本说明为准。文末保留调整前的历史验证范围，不将旧累计预算的测试结论视为本轮验证结果。

## P1：阶段门槛与结构化成果

每个阶段可以显式选择 `gate`：

- `none`：保留原有行为，运行成功即可完成阶段。
- `manual`：运行结束后进入 `waiting_confirmation`。用户填写理由并确认产出；不予确认会继续等待，不调用模型或重做工具。
- `native_task`：仅 Native 支持。运行结束后进入 `waiting_verification`，用户在任务面板复核后显式检查条件。宿主读取该阶段回执指定的任务，检查完整运行身份、计划/验收修订和当前工作区指纹。默认核查当前任务全部条件；显式 `criterionIds` 可以限定本阶段相关条件，其他未验证条件不会把工作流运行改为失败。所选条件的定义引用必须完整、与当前任务匹配，引用的步骤必须已实现；仅有人工条件确认不会覆盖仍待实现的相关步骤。

通过门槛后，最后阶段完成工作流，其余阶段进入暂停，由用户明确继续。检查缺少任务、未确认条件、证据过期或文件变化会保留等待状态和原因，不会自动重试。等待验收的阶段不能修改原执行指令；陈旧阶段/尝试次数的确认被拒绝。

Native 执行回执保留任务及运行身份、修订、工作区指纹、观察到的文件变化、条件与证据引用、模型请求/工具调用/执行时长。每份回执最多 64 KiB，条件与证据最多各 32 项，文件变化列表各最多 64 项，并显式标记截断。摘要与结构化回执共同传给依赖阶段，属于需要核查当前内容的历史证据，不自动成为验收结论。完整日志仍位于运行与任务记录。

文件变化或证据列表截断本身不阻断验收：宿主重新读取权威任务核查所选条件及当前证据。条件定义引用缺失则继续等待，默认全部条件不能通过截断列表省略要求；显式条件范围仍可核查完整保留的相关引用。

`workflow:confirm` 和 `workflow:verify` 是显式用户操作。门槛等待保存后重启仍等待，不重新执行。取消或维护期间迟到的运行结果不能推进阶段；其已消耗用量仍保留。旧工作流缺少门槛或阶段权限字段时保留原有行为。

## 独立协作与交付质量

新建 Native 工作流默认明确选择“独立对抗验证”，也可选择自动协作、并行协作或单 Agent。前三者均保留宿主独立质量门禁，单 Agent 保留阶段执行与既有验收门槛。旧存档和 API 请求没有 `collaboration` 字段时继续原有行为，Claude 工作流不接收该 Native 策略。

实现阶段的完成候选必须经过独立审阅、反例检查和隔离命令验证；只有只读阶段的工作流在最后交付时进行一次独立静态检查。已有实现阶段的后续只读阶段不重复创建审查团队，最终交付前重新核对最新实现成果对应任务的完整工作区指纹。通过回执必须绑定当前任务、父子执行身份、实际交付正文和最终源码快照。

第一轮有阻塞问题时，主 Agent 收到结构化反馈并继续修复；第二轮使用新的三个子身份，重新检查源码、正文、原有问题及实际命令回执。没有结构化报告、检查失败、源码变化或两轮后仍有阻塞问题时，不进入完成状态。质量审查内部的两轮不增加阶段 `attempts`；原来的人工确认、任务验收和显式重试分别保留。最后阶段经人工确认后，新协作工作流仍需点击继续，重新核查最终版本再完成交付。

质量面板分别展示自动审查与人工验收。命令退出成功仅证明命令实际完成；检查范围和模型判断仍需审阅，不代表真实模型工程质量及三平台人工验收已经完成。当前交接容量与不能自动确认的情况见[多 Agent 说明](NATIVE-AGENT-DELEGATION.md#工作流独立质量审查)。

## P2：阶段权限与执行用量

`NATIVE_WORKFLOW_POLICIES_ENABLED` 在 P2 为 `true`，界面显示、下发由 Native 宿主强制的阶段权限。2026-10-16 起，Native 主 Agent 不再限制执行时长、模型请求次数和工具调用次数；工作流不再设置或下发跨阶段的累计预算。P1 检查点保持原来的普通执行权限；旧记录保存的字段不会因启用新默认值而被补写或提高权限。

启用后，Native 阶段的 `toolPolicy` 为 `read_only` 或 `standard`；新默认工作流的规划、审阅阶段严格只读，实现阶段使用会话审批。Claude 保留已有普通工作流，不能配置并宣称宿主未支持的严格只读或 Native 证据门槛。

旧记录中的 `run.budget` 保留用于兼容和历史核查，在当前 Native 工作流中已停用，不再以旧上限扣减下一阶段额度或阻断父任务。模型请求、工具调用和执行时长的实际用量仍跨阶段、失败、显式重试、取消及重启保留，以运行 ID 防止重复记账。用量记录不完整时明确显示待核查，不推断为零，也不据旧累计额度自动重做已执行操作。

用量累计的是阶段实际执行用量。阶段间暂停、人工确认或验收等待、排队消息的等待时间不计为阶段执行时长。普通聊天队列与工作流分别记账，排队消息完成不会增加或重置工作流阶段用量。

每个子 Agent 仍由宿主独立限制预算，在「设置 → 运行与权限 → 运行限制」调整默认或当前会话配置：运行时长默认 30 分钟、最大 300 分钟；模型请求默认 60 次、最大 200 次；工具调用默认 120 次、最大 400 次；并发默认 4 个、最大 30 个。子 Agent 各自计数和计时，不共享总额度或累计总时长；等待自身审批只暂停自己的时钟。运行开始时捕获配置，下一轮才使用后来保存的修改。

并发容量由本轮父任务池统一分配，普通委派和独立质量角色共用，不能因进入审查阶段额外突破上限。批量工具一次可提交 1–30 个任务，超出空闲容量的任务按 FIFO 等待；等待执行名额不创建子预算或实现 worktree。准备、worker、清理与回执结算完成后才释放名额并启动下一项；工具仍等待整批返回。父任务取消或宿主重启不会自动恢复等待项，执行或清理未知时停止补位并保留隔离，细节见 [队列与自动补位](NATIVE-AGENT-DELEGATION.md#队列与自动补位)。

普通子 Agent 失败或自身预算耗尽不使整个阶段自动失败；父 Agent 收到保存的结果后可继续工作，并可在核查后用 `recover_agent` 建立新身份、上下文和独立预算，在保留的工作区完成剩余任务。恢复不重放旧工具或命令。执行、持久终态、物理清理或工作区状态未知时继续隔离并拒绝自动恢复；这类情况必须先核查真实状态，不能按普通失败处理。主阶段自身失败后的显式重试和阶段最大尝试次数保持原有行为，父任务成功也不替代阶段门槛核验。恢复细节见 [多 Agent 委派](NATIVE-AGENT-DELEGATION.md)。

## 历史本地验证范围（2026-10-16 策略调整前）

以下为较早实现登记的机制验证范围，包含当时启用的累计预算与耗尽阻断行为；这些历史行为已被上述独立子预算策略取代。本轮的类型检查、测试、图形回归和平台验收应独立登记，不能继承旧结论。

新增工作流、IPC 和呈现回归覆盖门槛与运行结果分离、部分条件验收、工作区/身份/修订变化、截断条件、异步验收与取消、真实存档及重启、成果交接、失败与取消的累计用量、重复存档记账拒绝、预算耗尽与未知用量、旧记录兼容和不支持的严格策略。

Electron 回归使用真实 Native utilityProcess、HTTP/SSE fixture 和生产界面：人工拒绝与确认不新增模型请求或重做工具，明确继续后各阶段仅运行一次；人工核验后文件变化会被阶段检查重新识别，工作流保留等待，任务面板显示证据过期，并保存实际按钮与状态截图。

P2 图形回归核对默认规划/审查只读工具目录和实现阶段普通目录、界面预算的真实累计；门槛等待期间执行超过工作流时长上限的独立排队回合，不改变工作流已用额度，确认后仍能完成剩余阶段。模型请求失败后手动重试累积到总上限时，下游阶段保持未执行，继续也不会重新下发请求。

本地定向测试不替代真实模型的工程质量、真实服务兼容性和正式平台验收。
