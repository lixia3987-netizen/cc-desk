## 用法与输出含义

现有 E0 工具可以初始化 12 条记录、执行独立代码验收并汇总报告，但此前仅在比较报告时提示部分参数缺项。新增命令在运行前读取完整固定矩阵，逐轮列出尚未填写或需要人工核查的字段：

```sh
node scripts/native-eval.mjs engineering-init /absolute/e0-batch <完整应用commit>
node scripts/native-eval.mjs engineering-readiness /absolute/e0-batch
```

用户明确不设评估上限时，新批次使用 `engineering-init /absolute/e0-batch <完整应用commit> --unlimited-budget`。此参数生成记录 schemaVersion 2，以 `"unlimited"` 表示明确无上限；原用法继续生成 v1 记录。未知值仍为 `null`，已发生费用和用量仍须如实登记，不能使用 `unlimited`。它不改变应用的单回合运行限制。

已有批次只执行第二条命令。检查不创建或覆盖报告，不改记录、不删除锁、不恢复或重跑验收，不读取凭据/配置引用指向的内容，不执行候选代码、不访问模型服务。需要保存输出时由操作者另存到新的文件，保留原记录。

| 退出码 / status | 含义 |
| --- | --- |
| `0` / `metadata_complete` | 12 条初始记录的声明字段齐全，且没有发现既有运行、验收尝试或遗留锁；不表示可授权执行 |
| `1` / `blocked` | 有合法但缺失/不充分的字段、矛盾预算、既有运行/验收记录或遗留锁，按逐轮 `issues` 与批次 `blockers` 核查 |
| `2` | 参数、批次、固定套件、文件或记录结构不合法，未给出完整性结论 |

`summary` 的完整/阻塞计数按轮次统计；批次遗留锁另列在 `blockers`，即使 12 条字段齐全，整体状态仍为 `blocked`。检查结果只描述本次读取的记录，不锁定之后的修改，也不是执行时的授权门禁。

输出仅包含固定身份、摘要、计数、字段名及原因码，不回显模型、配置引用、凭据来源、审批策略、停止条件或历史日志的原文。损坏 JSON 或文件读取错误使用固定错误消息，避免把记录片段或路径带入诊断。

## 检查范围

- 每轮检查模型、协议、配置引用、凭据来源引用，以及请求、工具、输入/输出、主动时长、总时长、费用币种、审批策略和停止条件的声明。
- 正式工程任务所需的六项执行额度为正数，或在记录 v2 中显式填写 `unlimited`。时长约束须一致：两个有限值要求主动时长不大于总时长，无限主动时长不能配有限总时长；有限主动时长配无限总时长有效。零费用预算允许，但不会被解释为服务实际免费；无上限费用可以不指定预算币种。空白停止条件不能作为已填写。
- 有任意验收尝试、已有运行结果/证据/指标（包括零指标或 `false`）时，提示已有现场需要核查，不把它称为全新可复用轮次。未知尝试和遗留锁均保留，检查不自动清理。
- 沿用完整 12 条记录、身份与固定套件、文件尺寸、路径别名和尝试绑定校验。旧 schema、历史报告、独立验收命令及 `evals/native-engineering/v1/` 材料保持不变。旧 schema 已拒绝的空白必填文本等仍按非法记录退出，不悄悄归一化。

即使状态为 `metadata_complete`，输出仍固定为 `executionAuthorized: false`、`runtimeStatus: not_checked`、`batchBudgetStatus: external_confirmation_required`，真实质量、图形和平台验收全部保持 `pending`。

1. Native 的服务、准确模型 ID 与协议；Claude 的实际 CLI/模型及账号方式。
2. 两边的配置与凭据来源引用，已确定的无上限评估预算，以及逐次审批和实际停止条件；应用既有运行限制另存配置快照。
3. 同一应用候选、12 份独立任务副本、外置验收器与实际运行环境，以及证据保存和人工复核安排。

只填写引用不会证明服务可用、凭据有效、预算得到执行器或服务商强制执行，也不会证明两个引擎条件等价。未取得这些正式条件时，保留缺项；不把本地准备或参数完整性升级为真实任务通过。
