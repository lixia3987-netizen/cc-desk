# 阶段四 P4b 第二批：发送前自动上下文压缩

日期：2026-09-28（北京时间）。基线：`feat/native-agent-recovery-context@491e44ee221fc9698faab1643b1cbc6d31135b46`，对应 [PR #35](https://github.com/lixia3987-netizen/cc-desk/pull/35) 的三平台完整技术验收。

开发分支：`feat/native-agent-auto-compaction`，继续使用堆叠 Draft PR，不合并主线或集成分支，不发布 Release。Claude 仍是默认引擎。

## 触发与预算

- 新配置 `autoCompact` 默认为 `off`。用户可在会话或引擎默认配置中选择 `before_send`（发送前自动压缩，可能计费）；启用、列表刷新和启动应用本身不调用模型。
- 只在已准入的新回合、普通任务 worker 启动前检查。估算使用权威协议历史、本次新输入和重新读取的项目指令；输入预算或上下文字节预算达到 90% 且有完整旧回合时，尝试一次摘要。不在工具执行或审批中途压缩。
- 本轮摘要沿用手动压缩：原服务与模型、无工具、单次请求、最多 4,096 输出 tokens / 60 秒、不自动重试，保留最初用户目标与最近完整回合，原始账本不删除。摘要有损，不保证保留全部约束。
- 摘要计入本次模型请求次数及活动时长，普通任务只获得剩余预算。仅有一次请求额度、或新输入与项目指令本身已超预算时，不付费请求摘要。
- 压缩后重新读取项目指令并检查本次输入是否仍超硬上限；不连续摘要直到达标。没有可压缩旧回合时，沿用原任务的预算停止行为。

## 持久化与重试

网络调用前追加并 fsync `context_compaction_attempted`，记录提交 ID、输入与当时规范化配置摘要、上下文指纹及账本版本。它不修改模型上下文、不创建普通 run，也不执行工具。

同一提交或同一份上下文只登记一次自动摘要。未完成或失败的尝试在重启后仍阻止隐式重试；记录只证明一次尝试，不声称已知实际扣费。成功 `context_compacted` 原子关联尝试并保存摘要用量。提交成功但普通 run 尚未开始时，相同消息可继续普通任务，不重新请求摘要。

摘要失败、不能缩小上下文或取消时，不发送普通任务请求；队列暂停并保留原消息，工作流沿用阶段失败处理。用户可以手动压缩，或显式关闭自动压缩、调整预算后继续保留的消息。尚未创建普通 run 时允许该配置调整；输入身份不能更换，旧摘要授权不会用于新的摘要调用。已有普通 run 回执仍先查回执，并按规范化配置核对，以兼容旧版缺少默认字段的历史。

自动过程始终持有同一个 ActiveRun、连接占用、会话准入及目录租约。取消停止本次发送，并等待 worker 实际释放；清理未确认继续阻止其他工作。摘要已经提交后取消后续发送，已保存摘要仍保留。

## 显示与兼容

预算面板显示开关、固定阈值、正在自动压缩、取消影响、最近手动/自动压缩以及未完成尝试的处理指引。失败提示从原始账本重建；历史消息保持不变，追加独立系统说明。

新版本读取 P4a/P4b 历史与旧提交回执。新增配置字段及自动尝试事件不受旧版本支持；不要用旧二进制继续写入本版本已更新的会话，保留数据并使用兼容版本。

## 验证与后续

账本回归覆盖同请求/同上下文去重、输入配置冲突、成功关联、模糊 fsync、重启及手动维护兼容；执行器使用本地 HTTP/SSE 验证真实调用次序、预算扣除、最新输入/指令、取消、失败及旧回执。正式 Electron E2E 覆盖 UI 配置持久化、自动压缩后发送、取消后的队列和重启、关闭自动化后继续原消息。
