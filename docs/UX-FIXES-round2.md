# 第二轮：对话检索、旧消息阅读与待处理请求

本轮接续第一轮 UX01–UX09 修复，落实日常效率规划中的会话内查找、旧消息分页和统一待审批入口。改动仍属于待发布的 v0.2.3 源码。

## 已交付

| 功能 | 使用方式与行为 |
| --- | --- |
| 会话内查找 | 结构化对话点击“查找消息”，或 Ctrl / ⌘ + F。搜索本地保留的消息正文、工具名称和输入，忽略大小写；显示摘要和匹配文字，点击后定位并标记原消息，工具卡片自动展开。 |
| 旧消息分页 | “查看更早消息 / 查看较新消息”在历史页之间导航，每页最多 50 条。“返回最新对话”恢复实时消息和自动跟随。 |
| 阅读位置 | 历史页独立于实时消息；切换会话后按原消息和偏移恢复阅读，保留输入草稿。修复了初次显示最新快照时覆盖历史阅读锚点的回归问题。 |
| 待处理总入口 | 顶栏显示所有项目中有效的审批与提问数量，列表区分会话、项目和请求类型。点击后清除阻挡导航的侧栏筛选，打开对应会话并聚焦请求卡片。 |
| 请求过期 | 列表由当前 CLI 进程的真实请求生成；响应、中断、取消、停止后更新。点击前及进入会话后均重新校验；重启不会恢复旧进程的审批。入口不代替用户作出决定。 |

界面预览：[查找消息](screenshots/conversation-search.png)、[历史阅读](screenshots/conversation-history.png)、[待处理请求](screenshots/attention-center.png)。新增控件使用现有主题颜色与模态键盘焦点规则。

## 数据与性能边界

- 实时快照仍为 400 条 / 2 MiB。分页和查找按需读取工作台 `.jsonl` 日志，日志保持原样；不会为浏览历史启动 CLI 或调用模型。
- 内存只缓存最近两个会话的消息字节位置索引，追加日志增量更新。单索引上限 100,000 个消息标识、标识总长 16 MiB，超过时明确提示导出。索引不持久化；启动后的首次检索需要扫描日志，不声称具备持久化全文索引的性能。
- 历史页最多 50 条、消息合计约 1 MiB；单条正文和工具输入分别显示最多约 16 Ki 字符，过长内容明确标记省略。搜索定位时截取包含匹配文字的片段。
- 每段搜索最多返回 50 条匹配或检查 1,000 条消息，通过“继续查找”读取更早结果。零匹配但仍有更早记录时提供继续入口，不把当前段数量说成全会话总数。
- 单条 JSONL 记录读取上限 32 MiB；片段拼接的单条文本也有上限。损坏行、未完成尾行、过长文本和部分 CLI 导入保留“不完整”提示。较早仅导入尾部的 CLI 原始历史不会被虚构为已完整纳入本地搜索，仍可导出原始记录查看。
- 只依据消息身份和已有日志证据排除旧的 result 回声；不同消息的相同文字仍保留。翻页游标按消息身份定位，新回复到来不改变此前游标的含义。
- 阅读位置与偏移在当前应用运行期间恢复；跨重启的阅读进度、未读计数、截图粘贴、面板调整和 Markdown 导出仍属于后续工作。
