# Claude Code CLI 更新

这项功能自 cc-desk v0.4.0 提供，更新当前连接的本机 Claude Code CLI；v0.3.0 安装包不包含此功能。cc-desk 桌面应用自身仍需手动下载安装新版本。

本文使用方式描述阶段二当前源码，**只维护 Claude 会话**，正在验收，见 [阶段二验证记录](ENGINE-BOUNDARIES-PHASE-2-VALIDATION.md)。已发布 v0.4.0/v0.5.0 使用的是停止全部工作区的旧行为；本说明不表示已有安装包获得了新行为。

## 使用方式

1. 每次启动 cc-desk 后会在后台检查版本。发现可用版本时，顶部显示当前版本、可用版本和「更新 CLI…」「暂不更新」。暂不更新只隐藏本次提示，下次启动仍会检查。
2. 点击「更新 CLI…」后，原生确认窗口会说明 Claude 会话及运行进程数量：Claude 图形化任务、原生终端、相关子进程和工作流会停止，Claude 待发送队列会暂停。**Shell 和其他引擎继续运行**。默认选中「取消」；取消不会停止正在运行的任务。
3. 选择「停止 Claude 会话并更新」后，应用阻止新的 Claude 执行、创建/导入和配置修改，等待目标进程、子进程、启动准备和关闭资源释放，并保存记录。任何目标停止或关键保存失败都会取消更新。Shell 和其他引擎仍受正常并发容量与工作目录管理限制。
4. 更新期间显示进度阶段，暂时不能切换 CLI 路径或重复更新。尚未开始安装时，退出请求会取消待执行的更新；进入 `updating` 后，安装及结果检测/能力刷新期间会提示等待完成再退出，避免主动中断正在安装的 CLI。命令结束后重新检测 CLI 和实际版本，不会把“退出码成功但版本未更新”显示为更新成功。
5. 项目、worktree、会话身份、历史和已保存草稿保留；维护期间仍可阅读记录、导出、保存普通草稿或停止/取消。更新结束后不会自动重跑 Claude 任务、队列或工作流。确认已有结果后，可恢复终端、继续对话，或手动继续中断的工作流；Shell 和其他引擎不因维护结束而改变状态。

在「设置与连接 → 连接与终端」可随时查看更新状态或重新检查。CLI 路径有未保存的修改时，先「保存并检测」，再检查该安装的更新。网络或仓库不可达只影响检查，不妨碍现有会话。

## 更新来源与安装方式

- 通过 `claude update` 更新选定的 CLI，支持原生安装及 CLI 自身支持更新的 npm 安装。沿用本机网络、登录、仓库与安装权限，不下载并执行额外安装脚本，不自动提权，也不迁移安装方式。
- npm 安装通过 `npm view` 读取版本，沿用 npm 的用户配置与环境变量，可使用已配置的镜像仓库；其他安装查询 Claude 官方发布通道的版本元数据。版本比较按数字进行，不会把 `2.1.9` 当作比 `2.1.10` 更新。
- 检查读取 Claude 用户及本机托管配置中的 `autoUpdatesChannel`，区分 `latest` / `stable`；尊重 `DISABLE_UPDATES`。实际更新仍由 CLI 执行并遵循其组织策略和版本限制。
- Homebrew、WinGet、apt 等包管理器安装依赖其更新机制；如果 `claude update` 未升级当前可执行路径，应用会提示失败，并引导使用对应包管理器，再回到设置重新检测。cc-desk 不改写这些包管理器的安装目录。
- cc-desk 启动的 Claude 会话关闭 CLI 后台自动更新，让应用内更新经过确认；不会改写 Claude 的全局配置。外部终端中单独启动的 Claude 及其更新行为不受 cc-desk 管理。
- 检查有网络超时，更新命令有 10 分钟超时；超时会终止更新进程树。失败后 Claude 会话保持断开，Shell 和其他引擎继续运行，可检查网络、安装权限或 CLI 路径后重新检查。正常退出的安装保护不会取消这一超时机制。命令的原始输出不会透传到界面，避免暴露仓库凭据或代理信息。

## 已知网络限制

更新检查不会将 Claude `settings.json` 的 `env` 中配置的代理转发给版本查询。这些设置仍可能由 Claude 会话自身读取，因此“对话正常，但更新检查失败”可能同时发生。npm 版本查询使用 npm 自身配置及 cc-desk 进程继承的环境；原生安装的版本查询由应用网络层执行。仅在 Claude 配置中填写代理，不能保证两条更新检查路径可达。

v0.4.0 未修复这项限制。检查失败时可在原有终端或包管理器中按既有方式更新 CLI，再回到工作台重新检测；失败不会触发安装或断开工作区。
