# 阶段四 P4c：MCP stdio 本地服务

日期：2026-09-28（北京时间）。基线：`dev/native-agent@cb0d9092835fb069fffc2fe22c879e98a2779548`（PR #41）；开发分支：`feat/native-mcp-stdio`。本批增加显式配置的 `2025-11-25` stdio 同步工具，在本地验证后仅合入 `dev/native-agent`。Claude 仍为默认引擎，P5 只进行功能替换；默认值切换由用户后续明确决定。本批不修改 main、不发布 Release、不触发 CI。

## 配置与使用

在「设置与连接 → MCP 连接 → Native Agent Alpha · MCP 连接」新增连接，明确选择「stdio · 本地可执行程序」。HTTP 新连接和没有传输或版本字段的旧连接仍保持 HTTP / `2026-07-28`；HTTP `2025-11-25` 兼容路径不变。stdio 固定 `2025-11-25`，不协商降级，不把 HTTP 失败转换为程序启动。

| 字段 | 填写方式与边界 |
| --- | --- |
| 可执行程序 | 已安装程序的本机绝对路径；不支持 `.bat` / `.cmd`，不自动搜索、下载或安装程序 |
| 启动参数 | JSON 字符串数组，每项原样传递，不拆分空格、不展开变量、不经 shell 解释；最多 128 项，序列化后最多 32 KiB |
| 工作目录 | 固定为本回合授权的项目 / worktree 根目录，不从连接配置覆盖 |
| 环境变量映射 | JSON 对象，键为子进程变量名，值为应用主进程已有的变量名；最多 16 项，只保存名称 |
| 认证 | stdio 不使用 HTTP Bearer 配置；需要密钥的服务通过上述变量名映射获取 |

例如，macOS / Linux 的程序字段填写本机实际 `node` 绝对路径，参数填写 `["/实际路径/server.mjs", "包含空格的单个参数"]`。Windows 可填写实际 `node.exe` 绝对路径，参数使用 JSON 转义的脚本路径，例如 `["C:\\项目\\server.mjs"]`。应用不会自动生成 npm / npx 安装或启动流程。

环境映射 `{"API_KEY":"MY_MCP_API_KEY"}` 表示从主进程读取 `MY_MCP_API_KEY`，只给该连接的受管进程设置 `API_KEY`。真实值不进入渲染器、连接文件、启动审批、模型 worker、模型请求或审计日志。目标变量不能覆盖系统启动变量、运行时注入变量或保留名；变量名大小写重复也会拒绝。每个解析值最多 8 KiB，名称与值合计最多 32 KiB。服务继承经过筛选的必要系统环境及明确映射的值，不复制完整主进程环境。所有映射值均按敏感值保护，短值或常见文本也可能触发防回显限制；普通非敏感开关建议使用参数传递。

不要把密钥写入程序路径或参数：这些属于可见、可持久化的配置和审批内容。stdio 不是沙箱，获准启动的程序可以使用当前用户权限访问文件、网络和其他资源；应只选择自己信任的程序。启动文件身份复核和进程收束不能将不可信程序变成受限程序。

保存、刷新、读取列表与检查「本机配置就绪」只处理本机配置，不启动程序、不读取工具目录，也不代表已验证程序可运行或兼容。切换传输方式会清除不适用的端点、程序参数、环境映射与认证方式；切换传输或 HTTP 版本会清空未提交的凭据输入。运行及清理期间不能修改连接，移除所有会话引用后才能删除。旧版本可能不认识新增字段，应保留数据并使用支持 stdio 的版本。

随后在 native 会话「运行配置」中读取 MCP 连接、明确勾选并保存。默认空选择，HTTP 和 stdio 合计最多 4 项；停止会话后修改，下一回合生效。

## 启动审批、工具调用与恢复

发送任务后，每回合对全部选中的 stdio 服务发起一次启动审批。审批展示连接、程序、字面参数、工作目录和环境变量来源名称，不包含环境值。该审批绑定提交与运行身份、连接修订、项目指令 / Skills 摘要及可执行文件的实路径和文件身份；批准后重新核对，并在每个 stdio 服务实际启动前再次复核，避免前序服务的目录等待使检查失效；已知变化使审批失效。stdio 服务只在批准后的本回合存活，不跨回合复用。

程序启动本身可能产生副作用，因此在启动任何所选 stdio 服务前，主进程先持久化 `startup_prepared`。记录成功后才进入程序启动和工具目录发现；发现失败时，也会清理此前已经启动的同批客户端。每次 `tools/call` 继续走原有独立工具审批，启动审批不授予工具免审批权限；服务声明只读也不能跳过审批。

正常完成、拒绝后续工具、停止、预算耗尽、协议错误和 worker 异常均进入本回合的清理流程：结束待处理请求，关闭 MCP 客户端，等待所属进程与相关句柄收束，确认后持久化 `startup_closed`，最后释放目录占用。进程管理沿用 guardian、Windows Job 与 POSIX 进程组；这用于管理应用持有的进程生命周期，不保证约束主动逃逸的恶意程序。

应用重启后，若发现 `startup_prepared` 没有对应的 `startup_closed`，即使尚未创建模型回合，也按未知副作用保留恢复屏障，阻止重复启动。新进程不能替旧进程确认清理。已收束但没有模型回执的旧提交也不重新启动服务，需用户显式发送新任务；已有模型回执的重复提交只有在启动记录已关闭时才直接返回既有结果；启动未关闭仍保留恢复屏障。清理或写入关闭记录失败时，目录继续隔离。

工具调用写出后发生超时、取消、断流、异常退出、无效结果或秘密回显，仍按结果未知处理；不自动重启服务、不重放调用。取消通知和进程退出不能证明副作用未发生。解除隔离前须检查项目文件、本地服务进程及它调用的外部服务；确认只解除隔离，旧会话保持只读，不重新执行未知操作。

## 协议子集与限额

stdio 使用 UTF-8、每行一条 JSON-RPC 消息：`initialize` 校验准确版本与服务能力，随后发送 `notifications/initialized`，再分页 `tools/list` 与同步 `tools/call`。同一回合复用初始化状态，后续回合重新审批并启动。客户端只声明本批支持的能力；支持有界 ping 响应，其他服务端请求返回不支持，不执行其 instructions、脚本、资源链接或额外请求。

stdout 只能承载协议数据，非法 UTF-8、错误 JSON、错误关联 ID、不完整帧及协议污染会关闭该客户端。stderr 持续读取并丢弃，不混入协议、不积累为日志，也不回显服务原始错误。已知敏感值的回显检查适用于工具目录、消息和结果；不能安全保留的结果不会进入模型或审计。

| 限额 | 当前实现 |
| --- | --- |
| 单条入站协议帧 | 最多 1 MiB |
| 单次操作累计 stdout | 最多 2 MiB，包含期间通知 |
| 单个 stdio 客户端累计 stdout | 最多 32 MiB |
| 单条出站请求及待写入数据 | 最多 128 KiB |
| 单客户端服务端请求 / 通知 | 最多 8 次请求、128 条通知 |
| 目录读取 | 每个服务最多 8 页；所选服务合计最多 64 个工具、128 KiB 目录 |
| 工具 schema | 单 schema 最多 16 KiB，沿用有界 JSON Schema 子集 |
| 工具输入 / 参与 schema 校验的结构化输出 | 各最多 64 KiB，根类型为对象 |
| 准备与操作超时 | 目录准备最多 30 秒，且不能超过剩余回合预算；协议操作默认 30 秒 |
| 取消通知 | 最多等待 2 秒；不作为服务停止或未执行的证明 |

工具定义计入普通请求、自动压缩前判断和预算展示；不支持的 schema 或必须使用异步 tasks 的工具会被排除。结果仅接受文本 / JSON，沿用 [MCP 共用审批、预算与恢复边界](NATIVE-AGENT-PHASE-4C-MCP.md)。固定 2025 的输入、结构化结果及输出 schema 根必须是对象；不宣称完整 MCP 或完整 JSON Schema 兼容。

本批仍不提供自动安装、全局服务导入、旧 HTTP+SSE、其他协议版本、自动回退、OAuth、tasks、roots、sampling、elicitation、prompts/resources、订阅、图片 / 音频或自动读取资源。P4c 整体未完成，更多模型协议与完整 Skills 管理仍待后续推进。
