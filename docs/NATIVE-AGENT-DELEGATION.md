# Native 多 Agent 委派

Native 宿主提供 `delegate_review` 和 `delegate_implement`。每次调用可以并行委派 1–4 个有明确目标的子任务，一个父回合最多启动 16 个子任务。子任务有独立模型上下文、utilityProcess、任务记录、运行账本和进程监督器，不能继续委派。模型回复、工具结果和执行完成都不自动代表验收通过。

## 权限与工作区

只读审阅使用父工作区当前内容，宿主仅提供本地读取、搜索、任务计划和代码位置工具。子任务没有写文件、命令、MCP 或继续委派的能力。实现任务使用独立 Git linked worktree 和 `codex/native-agent-*` 分支，每次写入和命令都在父会话显示审批，并注明子任务、执行身份和工作区。子任务不创建侧栏会话。

实现委派必须明确选择基线：`snapshot` 包含当前工作区的已暂存、未暂存及非忽略的新文件；`head` 仅接受干净的父工作区。快照与成果补丁使用独立临时索引，父分支、HEAD、实际索引和文件保持原样。当前不接受 Git 子模块基线。各子任务使用同一批次基线，但分别修改自己的 worktree，不自动合并或删除成果。

父任务保有父工作目录的占用权限，实现子任务另持有其 worktree 目录权限。每次工具操作再次核查父代次、子任务身份和目录归属。取消父任务会取消所有子任务，并等待模型 worker、命令、回执与元数据关闭；未知效果或清理失败继续保持隔离。重启后，从父运行绑定的持久回执恢复子工作区隔离，不能通过新会话进入尚未确认的子工作区。

## 预算和审批

父模型请求、摘要请求以及全部子任务共享宿主的原子模型请求和工具调用额度。请求在联系模型前预留，工具在准备和副作用前预留；并行子任务不能分别花费一份完整的父额度。执行回执使用共享累计值，工作流据此扣除剩余额度。失败、取消和重启不会补回已消耗的额度。

审批仍有墙钟有效期。父会话中可见的人工审批等待从共享执行时长中排除，并同步暂停父及兄弟 worker 的执行计时器；等待队列不重复扣除同一段暂停。取消信号在暂停期间仍立即生效。

## 产物与验收

`native/delegations/<父 conversation>/<父 run>/<batch>/<child>/receipt.json` 保存子任务及父任务的完整身份、目标、状态、模型与工具计数、工作区、补丁路径和证据引用。子任务的原始模型/工具账本、任务快照和命令回执独立保存。工作区成果保留修改、新文件和删除的文件。

会话默认展示最近四个子任务，运行中的优先；可展开同一父回合最多 16 个子任务。开始没有新委派的父回合后，仍保留最近一次有委派的父回合成果入口。更多结果仍保存在原始记录中。准备中或运行中的记录在重启且没有活动 worker 时显示未知；缺少持久终局、身份不匹配或 `recovery_required` 不会显示为普通完成。

“查看保存成果”按父运行和子任务身份读取宿主保留的目标、摘要、补丁、哈希与命令验证回执。补丁按字符边界分页并绑定同一 SHA-256，以纯文本展示；新记录与保存时的哈希校验，旧记录缺少原始哈希时明确标为 `legacy_unverified`，当前读取生成的摘要不能证明其自保存以来未变化。保存补丁仅反映记录时版本；隔离分支不代表改动已提交或已合入。读取失败保留明确错误，关闭或切会话后迟到响应不更新查看器。任务快照和原始命令日志当前提供路径引用，不能当作日志正文已阅读。

用户可以填写审阅意见，选择交给父 Agent 审阅/整合或要求修改。操作只把成果身份、补丁哈希及意见追加到现有输入框，并关联宿主结果提供的 `parentTaskId`；界面显示下一条消息将继续该任务，用户可取消关联。既有草稿不被覆盖，合并后超过 60,000 字符时拒绝追加且不改变任务关联。未点击发送时不发模型请求、不修改工作区；归档、只读、历史阅读或维护状态可以查看成果，但不能交接。未知结果使用核查入口，不推导自动采纳。

父 Agent 可通过只读 `read_agent_result` 读取绑定当前父会话账本的历史子成果，宿主校验完整父子身份、受控路径与分页哈希；模型不能用任意路径或另一会话身份越界读取。子 Agent 不获得这一跨成果入口。后续修改使用新的委派身份和隔离工作区，旧子运行不被接管；整合仍由父回合读取当前文件、生成明确变更并逐次请求既有写入或命令审批，不自动合并、提交、删除工作区或重放旧工具。

父任务的验收条件仍由现有任务证据与人工复核决定。审阅意见目前作为用户草稿和后续消息保留，不建立独立的人工验收回执。审阅者需要检查子任务产物和实际验证结果，再确认工作流阶段；委派工具结束、成果读取、意见交接和文件整合均不直接推进验收门槛。

## 验证范围

本地回归覆盖真实 Git 快照和成果保留、任务与运行绑定、目录互斥、宿主配额、审批、取消及重启恢复。Electron 回归使用生产 utilityProcess 和可控 HTTP/SSE 模型 fixture，确认实际并行、独立上下文、父审批与进程关闭。这些验证覆盖执行机制，不替代真实模型的工程质量评估。

历史验证（2026-10-08，成果审阅交接改进之前）：Windows 构建、Desktop 类型检查以及定向执行、生命周期、目录隔离、委派和投影回归通过；扩展 Electron 回归同次 22/22 通过，覆盖多 Agent 的四项实际进程用例，以及原有 Native 任务、自动压缩、回合内压缩和 workflow 验收/预算。审批范围由独立宿主字段验证，模型参数不能伪造子任务身份。本轮最终候选的结果在验证完成后另行登记，不能继承历史计数。
