# Native 多 Agent 委派

Native 宿主提供 `delegate_review` 和 `delegate_implement`。每次调用可以并行委派 1–4 个有明确目标的子任务，一个父回合最多启动 16 个子任务。子任务有独立模型上下文、utilityProcess、任务记录、运行账本和进程监督器，不能继续委派。模型回复、工具结果和执行完成都不自动代表验收通过。

## 权限与工作区

只读审阅使用父工作区当前内容，宿主仅提供本地读取、搜索、任务计划和代码位置工具。子任务没有写文件、命令、MCP 或继续委派的能力。实现任务使用独立 Git linked worktree 和 `codex/native-agent-*` 分支，每次写入和命令都在父会话显示审批，并注明子任务、执行身份和工作区。子任务不创建侧栏会话。

实现委派必须明确选择基线：`snapshot` 包含当前工作区的已暂存、未暂存及非忽略的新文件；`head` 仅接受干净的父工作区。快照与成果补丁使用独立临时索引，父分支、HEAD、实际索引和文件保持原样。当前不接受 Git 子模块基线。各子任务使用同一批次基线，但分别修改自己的 worktree，不自动合并或删除成果。

父任务保有父工作目录的占用权限，实现子任务另持有其 worktree 目录权限。每次工具操作再次核查父代次、子任务身份和目录归属。取消父任务会取消所有子任务，并等待模型 worker、命令、回执与元数据关闭；未知效果或清理失败继续保持隔离。重启后，从父运行绑定的持久回执恢复子工作区隔离，不能通过新会话进入尚未确认的子工作区。

## 预算和审批

父模型请求、摘要请求以及全部子任务共享宿主的原子模型请求和工具调用额度。请求在联系模型前预留，工具在准备和副作用前预留；并行子任务不能分别花费一份完整的父额度。执行回执使用共享累计值，工作流据此扣除剩余额度。失败、取消和重启不会补回已消耗的额度。

审批仍有墙钟有效期。父会话中可见的人工审批等待从共享执行时长中排除，并同步暂停父及兄弟 worker 的执行计时器；等待队列不重复扣除同一段暂停。取消信号在暂停期间仍立即生效。

## 产物与验收

`native/delegations/<父 conversation>/<父 run>/<batch>/<child>/receipt.json` 保存子任务及父任务的完整身份、目标、状态、模型与工具计数、工作区、补丁路径和证据引用。子任务的原始模型/工具账本、任务快照和命令回执独立保存。工作区成果保留修改、新文件和删除的文件。

会话展示最多四个子任务及其实际状态，提供任务/运行身份、工作区、补丁和回执路径。更多结果仍保存在原始记录中。准备中或运行中的记录在重启且没有活动 worker 时显示未知；缺少持久终局、身份不匹配或 `recovery_required` 不会显示为普通完成。

父任务的验收条件仍由现有任务证据与人工复核决定。审阅者需要检查子任务产物和实际验证结果，再确认工作流阶段；委派工具结束不直接推进验收门槛。

## 验证范围

本地回归覆盖真实 Git 快照和成果保留、任务与运行绑定、目录互斥、宿主配额、审批、取消及重启恢复。Electron 回归使用生产 utilityProcess 和可控 HTTP/SSE 模型 fixture，确认实际并行、独立上下文、父审批与进程关闭。这些验证覆盖执行机制，不替代真实模型的工程质量评估。

2026-10-08 Windows 验证：构建、Desktop 类型检查以及定向执行、生命周期、目录隔离、委派和投影回归通过。最后一次扩展 Electron 回归同次 22/22 通过，覆盖多 Agent 的四项实际进程用例，以及原有 Native 任务、自动压缩、回合内压缩和 workflow 验收/预算；审批范围由独立宿主字段验证，模型参数不能伪造子任务身份。
