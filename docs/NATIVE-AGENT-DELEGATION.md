# Native 多 Agent 委派

本文描述 2026-10-16 调整后的当前源码；已发布安装包以对应版本说明为准。

Native 宿主提供 `delegate_review`、`delegate_implement` 和 `recover_agent`。子 Agent 并发默认 4，允许配置为 1–30；单次批量委派不能超过配置的并发上限和当前剩余名额。准备中及运行中的子任务占用名额，完成或失败并结束后释放；不再使用父回合累计最多 16 个子任务的限制。子任务有独立模型上下文、utilityProcess、任务记录、运行账本和进程监督器，不能继续委派。模型回复、工具结果和执行完成都不自动代表验收通过。

## 权限与工作区

只读审阅使用父工作区当前内容，宿主仅提供本地读取、搜索、任务计划和代码位置工具。子任务没有写文件、命令、MCP 或继续委派的能力。实现任务使用独立 Git linked worktree 和 `codex/native-agent-*` 分支，写入和命令按父会话权限模式审批；需要人工批准时，在父会话注明子任务、执行身份和工作区。子任务不创建侧栏会话。

实现委派必须明确选择基线：`snapshot` 包含当前工作区的已暂存、未暂存及非忽略的新文件；`head` 仅接受干净的父工作区。快照与成果补丁使用独立临时索引，父分支、HEAD、实际索引和文件保持原样。当前不接受 Git 子模块基线。各子任务使用同一批次基线，但分别修改自己的 worktree，不自动合并或删除成果。

父任务保有父工作目录的占用权限，实现子任务另持有其 worktree 目录权限。每次工具操作再次核查父代次、子任务身份和目录归属。取消父任务会取消所有子任务，并等待模型 worker、命令、回执与元数据关闭；未知效果或清理失败继续保持隔离。重启后，从父运行绑定的持久回执恢复子工作区隔离，不能通过新会话进入尚未确认的子工作区。

## 独立预算、设置和审批

主 Agent 不限制执行时长、模型请求次数和工具调用次数，其摘要与重试也不受子 Agent 预算限制。每次子 Agent 执行独立拥有下列额度，兄弟子任务之间不累加、不共享，父任务也没有跨子任务的总时长上限：

| 配置 | 默认值 | 最大值 |
| --- | --- | --- |
| 单个子 Agent 运行时长 | 30 分钟 | 300 分钟 |
| 单个子 Agent 模型请求 | 60 次 | 200 次 |
| 单个子 Agent 工具调用 | 120 次 | 400 次 |
| 同时活动的子 Agent 数量 | 4 个 | 30 个 |

在「设置 → 运行与权限 → 运行限制」选择「新会话默认」或「当前会话」后调整。时长以分钟显示和编辑。跟随默认的会话在下一回合读取已保存策略；单独设置的会话保留自身配置。运行开始时捕获整套配置，运行中的设置变化不改写该轮任务或历史记录。旧配置中已显式保存的数字保留，缺失字段采用上述新默认值；这些旧数字不再限制主 Agent。

会话协作区显示本轮真实生效的并发上限、配置来源、累计创建和当前活动数量。历史记录没有保存真实上限时显示未知；设置草稿不会改写运行中的数字。折叠四条只影响展示，全量计数取自宿主持久回执。旧会话默认保留自身配置，需要使用新默认值时可在会话配置中明确切换“跟随默认”。

当前用户消息中的明确并行数量支持 1–30 的中文、英文和数字表述；单 Agent、禁止委派、引用内容和否定句分别处理。数量上限代表可用容量，模型按独立问题、修改范围及验证风险安排任务，不固定选择四个，也不要求用满容量。当前仍按同步批次执行，不实现空闲名额自动补充的任务池。

每个子 Agent 从自身执行开始独立计时，包含其模型、工具、摘要和重试；请求及工具调用也分别在该子 Agent 内计数。并行执行不是把兄弟任务的时长相加。执行回执继续记录实际用量，工作流的累计用量用于查看，不再扣除共享剩余额度。

审批仍有墙钟有效期。子任务等待自己的审批（包括在父会话中排队等待审批）时，仅暂停自己的执行计时，父任务和兄弟子任务继续运行；不会暂停其他子任务的时钟。取消信号在等待期间仍立即生效。

## 子任务失败与恢复

单个子 Agent 的普通失败、请求／工具／时长预算耗尽会保存该子任务的状态和结果，父 Agent 与其他子任务继续执行。父 Agent 应使用 `read_agent_result` 核查已保存结果、失败原因、补丁及证据，再决定恢复、重新分工或在最终结果中说明尚未完成的部分；不能将失败结果当作已完成分析。

当前父回合可调用 `recover_agent`，指定失败或已取消的 `childId`，并可附上有界的继续目标。宿主先检查上一尝试已结束、终态已持久化、物理资源已清理以及工作区归属与内容仍一致；通过后创建新的子身份、上下文、账本和完整独立预算。实现任务复用其已保留的隔离 worktree，保留已有修改，并将旧结果和证据引用交给新尝试，只完成剩余工作。旧尝试与新尝试关联保留，旧用量及日志不会删除。

恢复不会重放旧账本、命令或写入，也不自动合并成果。`unknown`、`recovery_required`、缺失终态、进程清理未确认或工作区状态未知时，宿主拒绝自动恢复，受影响的目录继续隔离；需要先核查真实执行状态及已产生的操作。这类资源或副作用未确认与普通子任务失败分开处理，不能为保持父任务运行而解除隔离或盲目重复操作。取消父任务仍会取消其所有子任务。

## 产物与验收

`native/delegations/<父 conversation>/<父 run>/<batch>/<child>/receipt.json` 保存子任务及父任务的完整身份、目标、状态、模型与工具计数、工作区、补丁路径和证据引用。子任务的原始模型/工具账本、任务快照和命令回执独立保存。工作区成果保留修改、新文件和删除的文件。

会话默认展示最近四个子任务，运行中的优先；可展开同一父回合最近 30 个子任务，这一展示上限不限制父回合累计委派次数。开始没有新委派的父回合后，仍保留最近一次有委派的父回合成果入口。更多结果仍保存在原始记录中。准备中或运行中的记录在重启且没有活动 worker 时显示未知；缺少持久终局、身份不匹配或 `recovery_required` 不会显示为普通完成。

“查看保存成果”按父运行和子任务身份读取宿主保留的目标、摘要、补丁、哈希与命令验证回执。补丁按字符边界分页并绑定同一 SHA-256，以纯文本展示；新记录与保存时的哈希校验，旧记录缺少原始哈希时明确标为 `legacy_unverified`，当前读取生成的摘要不能证明其自保存以来未变化。保存补丁仅反映记录时版本；隔离分支不代表改动已提交或已合入。读取失败保留明确错误，关闭或切会话后迟到响应不更新查看器。任务快照和原始命令日志当前提供路径引用，不能当作日志正文已阅读。

用户可以填写审阅意见，选择交给父 Agent 审阅/整合或要求修改。操作只把成果身份、补丁哈希及意见追加到现有输入框，并关联宿主结果提供的 `parentTaskId`；界面显示下一条消息将继续该任务，用户可取消关联。既有草稿不被覆盖，合并后超过 60,000 字符时拒绝追加且不改变任务关联。未点击发送时不发模型请求、不修改工作区；归档、只读、历史阅读或维护状态可以查看成果，但不能交接。未知结果使用核查入口，不推导自动采纳。

父 Agent 可通过只读 `read_agent_result` 读取绑定当前父会话账本的历史子成果，宿主校验完整父子身份、受控路径与分页哈希；模型不能用任意路径或另一会话身份越界读取。子 Agent 不获得这一跨成果入口。新实现委派使用新的身份和隔离工作区；符合上述前提的失败恢复以新身份复用原工作区，旧子运行不被接管。整合仍由父回合读取当前文件、生成明确变更并按既有权限请求写入或命令审批，不自动合并、提交、删除工作区或重放旧工具。

父任务的验收条件仍由现有任务证据与人工复核决定。审阅意见目前作为用户草稿和后续消息保留，不建立独立的人工验收回执。审阅者需要检查子任务产物和实际验证结果，再确认工作流阶段；委派工具结束、成果读取、意见交接和文件整合均不直接推进验收门槛。

## 工作流独立质量审查

明确要求“使用 workflow／工作流分析或实现”的当前用户消息可触发宿主质量审查；引用、讨论问句和禁止使用工作流的内容不触发。这个入口在当前聊天回合内完成检查；右侧工作流面板用于创建有阶段和存档的工作流。明确单 Agent 时不创建质量子任务。

非单 Agent 的新协作策略在主回合提交终态前，创建独立审阅、反例检查、隔离验证三个新上下文。三者检查同一 Git 快照和实际待交付正文，正文 SHA-256、源码版本、真实文件读取及命令终态写入宿主记录。分析任务进行静态检查并明确没有运行命令；实现任务的验证者在隔离 worktree 中按既有权限执行检查，不能使用编辑工具、MCP 或继续委派。命令仍可能产生副作用，继续使用原会话的审批规则，核查前后源码变化会阻断通过。

问题包含优先级、实际读取位置、复现步骤和宿主分配的问题 ID。阻塞或高优先问题会要求主 Agent 在同一回合修复，第二轮使用全新的三个身份和更新快照，逐项提交修复证据。最多自动检查两轮，仍未通过则阻断交付；自动审查不生成任何人工验收通过记录，也不占用工作流阶段的手动重试次数。

质量记录位于 `native/workflow-quality/<父 conversation>/<父 run>.json`，原始子账本和任务记录分别保留。缺报告、未完整读取材料、遗漏实际失败命令、未知清理状态、取消、版本变化或重启时未结束的检查，都不会显示通过。当前质量交接最多包含 24 个材料文件，完整目标、正文及问题必须装入 6,000 字符的子任务交接；删除文件、工作目录范围外改动和无法完整观测的材料会明确阻断，不静默缩小验证范围。这些边界不限制普通聊天或旧委派工具。
