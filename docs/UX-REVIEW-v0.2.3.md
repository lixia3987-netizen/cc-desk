# v0.2.3 体验检查与后续开发建议

检查日期：2026-09-22。代码基线：`472cc1a9c6a18a50f6ed5742e228effc44ed53c0`。

目前最需要打磨的是连续工作的体验：输入不丢失、切换不打断阅读、当前项目不选错、连接问题能直接处理。建议先修复下列具体问题，再补长对话检索、后台任务入口和布局调整。

本次完成源码检查及 Linux Electron 隔离桌面复现，使用两个临时 Git 项目、结构化历史、Claude 终端和 Shell 会话。未启动真实模型请求；不将这些结果视为 Windows 原生安装、真实账号或系统通知验收。

## B. 值得补齐的客户端体验

以下是源码中尚无完整操作路径的能力，不等同于已复现的故障。建议以每行的最小交付范围推进。

| 方向 | 目前的缺口 | 最小交付范围 | 验收重点 |
| --- | --- | --- | --- |
| 首次连接与故障处理 | 有诊断信息，但安装、路径选择、登录和首次任务仍分散；缺少检测结果对应的处理入口。 | 首次连接步骤；原生路径选择；“已安装 / 已登录 / 请求验证”的独立状态；错误旁提供重新检测、打开目录、复制脱敏诊断。 | Windows 标准 npm、空格路径和新进程 PATH；取消操作不改配置；付费请求验证须由用户主动发起。 |
| 长对话阅读与检索 | 当前对话无消息搜索、整条复制、引用或消息定位。UI 快照有 400 条 / 2 MiB 上限，旧消息仅提示导出，没有向上加载入口。 | 先补会话内查找、上一处/下一处、整条复制和引用；再做旧消息分页加载及 Markdown 导出。 | 与已有“导入 CLI 历史”全文搜索区分；分页不重复、不丢消息，搜索结果可定位，加载后阅读位置稳定。 |
| 后台任务与审批 | 已有会话状态和可选系统通知；缺少待处理总入口、审批数量和未读标记。审批卡片在消息末尾，读旧消息时容易错过。 | 常驻待处理入口、每会话未读/待审批数量、跳到审批、跳到下一个需处理会话；展示工具名称、工作目录和关键参数。 | 不依赖系统通知权限也能发现任务；只响应仍有效的当前请求；展示完整参数入口，权限不自动放宽。 |
| 输入与附件 | 附件可选择并持久化，但没有截图粘贴、拖放、图片缩略图；运行时可继续编辑草稿，却不能明确排队。 | 优先支持粘贴截图、拖放和预览；后续增加显式“加入待发送”，可编辑、取消，标明所属会话。 | 附件复用原有类型/大小校验；切换会话不串附件；排队消息不在审批未完成时擅自发送，恢复后不重复提交。 |
| 布局与可读性 | 面板宽度固定；没有聊天/UI 字号设置；窗口尺寸及最大化状态未保存。现有字号只控制终端。 | 侧栏和检查面板可收起、拖动调宽；正文/UI 字号；窗口位置、大小及布局保存。 | 已看过 980×680 实际窗口，主聊天区约 470 px，未据此判定严重遮挡。新增布局需验证五套主题、系统缩放、键盘操作和屏幕变化后窗口可找回。 |
| 代码审阅与执行反馈 | 有文件 diff 和工作流摘要，但文件定位、任务耗时/最近活动、工具执行层级不完整；摘要不能代替测试证据。 | 外部编辑器打开文件/行号；更清楚的工具执行中、完成、失败状态；工作流结果链接到实际 diff、日志和测试结果。 | 不把 CLI 回合成功称为测试通过；输出可追溯到当前会话、阶段和项目；较大的 diff 保留截断提示。 |
| 项目和会话整理 | 缺少项目移除入口、项目路径重新关联、会话置顶等；默认标题区分度低，“最近会话”也未按最近活动重新排序。 | 项目移除与重新关联；会话置顶、按最近活动排序；用首条任务生成可编辑的本地标题。 | 移除项目不删除磁盘文件；重关联检查活动任务和隔离目录；排序不抢当前选择，保存用户修改过的标题。 |
| 更新、迁移与支持 | README 已说明无自动更新；应用内缺少版本检查和发布说明入口、诊断导出、整体备份/恢复。便携包的用户数据仍在 userData。 | 先加版本/Release 入口、脱敏诊断导出、手动备份恢复，再考虑自动更新。 | 区分已发布版本与仅完成源码的版本；备份包含附件和会话，恢复前核验与备份；诊断不含凭据；升级保留数据。 |

## C. 建议开发顺序

### 第一轮：修复连续操作

已处理 UX01–UX09：终端误报、三处草稿问题、默认项目、阅读位置、路径检测、准备按钮及 Git 刷新。已补充“输入 → 切换 → 返回 / 重启”和“修改路径 → 检测”等回归用例，详细范围见第一轮修复记录。

Windows 是当前用户的主要使用环境。交付时应增加 Windows 原生 npm CLI 启动、中文输入法、路径选择和重启恢复验收；隔离 Linux 桌面验证只用于提前发现公共界面逻辑问题。

### 第二轮：提高日常效率

按价值排序交付：会话内查找与旧消息加载 → 待审批/未读入口 → 面板调整和聊天字号 → 截图粘贴及预览 → 整条消息复制/引用和 Markdown 导出。每个功能保留可独立验收的边界。

### 第三轮：完善长期使用

项目与会话整理、连接引导和恢复工具、版本与备份入口、可追溯工作流产物，再逐步推进 MCP/Skills 管理、子任务树及高级 Git 操作。签名、公证、自动更新需要相应的证书和发布配置。

## D. 构建交付也需要优化

当前 [工作流](../.github/workflows/build.yml) 在每次 push / PR 都执行三平台校验和完整打包，发布仅在满足发布条件时发生；并发取消已有实现。建议把日常代码校验与发行打包拆开，纯文档变更跳过构建，完整原生验证和包测试继续作为正式发布门槛，并为临时产物设置明确保留期。

这些调整可减少不必要的运行量，但不能据此断言当前设置导致了账号限制，也不能解除 GitHub 的付款/支出限制。恢复发行前仍需解决账号问题；本次文档提交使用 `[skip ci]`，不重试受阻构建。
