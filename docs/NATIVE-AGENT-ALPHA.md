1. 从开发源码构建应用，在「设置与连接 → 模型与上下文 → 模型连接」登记自研 Agent 模型连接，明确选择 Responses、Chat Completions 或 Anthropic Messages，填写服务地址和准确模型名。此页仅管理自研 Agent，Claude Code 的模型配置由 Claude Code 管理。地址填写 API 基础地址，例如 `https://服务域名/v1`；适配器分别追加 `/responses`、`/chat/completions` 或 `/messages`。Anthropic 地址未带 `/v1` 时追加 `/v1/messages`，不自动回退。
2. 选择认证方式：从指定环境变量读取、仅本次应用进程保存，或使用操作系统安全存储。环境变量需由启动桌面应用的环境提供。密钥只经专用输入接口进入主进程，不写 workspace；仅内存模式重启后需重新输入。
3. 添加项目，新建 Agent 会话，显式选择「自研 Agent · Alpha」及连接。模型覆盖留空使用连接默认值。native 不依赖 Claude CLI 登录；Claude 会话继续使用各自的 CLI 配置。
4. 提交文字任务。列目录、搜索和普通文件读取在已选项目内执行；每次文本写入、命令及敏感文件读取都单独审批。检查文件内容、版本条件或 executable / argv / cwd，再允许本次或拒绝。
5. 查看实际 Git 差异、工具退出码和输出。运行中继续输入会进入文字队列；单会话串行工作流同样使用 native 执行器。

远程地址要求 HTTPS；回环 HTTP 仅在明确勾选后开放。禁止带账号密码、查询令牌、片段的 URL，并拒绝重定向。各协议分别保存原生上下文；兼容服务须支持所选协议的完整流式工具调用。Chat Completions 要求标准 `max_completion_tokens`、用量和完成事件，不隐式替换参数；Anthropic 使用 `max_tokens`、完整 Messages SSE 结束事件和客户端工具调用。支持 Anthropic `thinking`、`redacted_thinking`、思考与签名分片，完整私有块保存并原样续接；Kimi 缺少签名时保持缺省，不伪造签名。思考不显示为普通回复，也不在摘要请求中改写为用户正文。客户端不主动开启或关闭 thinking，不改变服务默认推理档位。非标准 reasoning 或服务端工具等未支持的活动消息块仍会明确拒绝；缺少完整结束事件时不会执行已解析的工具。

### 从服务地址读取可用模型

保存连接并配置凭据后，在连接卡片点击「读取可用模型」。使用已保存的服务地址和凭据请求列表：OpenAI 兼容服务在 API 基础路径追加 `/models`；Anthropic 地址未带 `/v1` 时追加 `/v1/models`，已有 `/v1` 时只追加 `/models`，网关前缀保留。格式依据 [OpenAI Models API](https://platform.openai.com/docs/api-reference/models/list) 和 [Anthropic Models API](https://platform.claude.com/docs/en/api/models/list)。此操作仅发送 GET 请求，不发送对话或项目内容，也不调用生成接口。

读取成功后选择「可用模型」，点击「切换模型」保存为此连接的默认模型；读取本身不修改配置，当前模型不在列表中仍会保留。已有上下文绑定原服务、协议和模型，更换模型需新建会话；单独指定模型的会话和新会话默认设置仍使用其显式选择。价格配置继续绑定原模型，切换不会沿用其费率。列表仅表示服务返回的模型，不保证它们均支持所选协议、图片或工具调用；服务不支持模型列表时可在「编辑」中手动填写模型 ID。

读取时支持取消，修改连接后需重新读取。请求总超时为 30 秒，限制分页、模型数量和响应大小，禁止携带凭据跟随重定向；错误只显示本地状态，不回显服务响应或凭据。

### 自动读取模型窗口与限制

自研 Agent 自动读取已保存连接的模型元数据。主进程优先 GET `/models/{模型 ID}` 的模型详情，字段缺失时从同一服务的 `/models` 目录补充，再查询有限的本地能力表；Anthropic 路径统一带 `/v1`。模型 ID 编码为单个路径段，只采用与请求模型完全一致的详情或目录条目。每个字段分别保留 `provider`、`catalog` 或 `fallback` 来源，部分详情不会覆盖目录或本地表的其他已知字段。当前读取上下文窗口、最大输入和最大输出 token；没有可靠数值的字段保持未知，不据模型名称前缀推测能力，也不据列表推断工具或图片支持。

自动读取总计最多等待 3 秒，复用列表的认证、分页、体积、重定向和凭据回显检查，只发送 GET，不带项目内容。请求按连接 ID、修订版和模型去重，成功结果缓存 5 分钟，失败结果缓存 30 秒；更换连接、模型或凭据后不复用旧绑定。自动读取不占用连接测试锁，期间仍可使用或修改连接；响应回来时再次核查修订版，过时结果不进入本轮预算。超时或取消保留已验证的详情字段，其余字段用安全的目录或本地表补缺。窗口重载、renderer 崩溃和退出会取消未完成的元数据请求。

本地表只匹配协议、官方主机、基础路径和明确模型 ID。Anthropic 部分核验日期为 **2026-10-02**，官方 `api.anthropic.com` 表含 `claude-fable-5-1`、`claude-opus-5-5`、`claude-sonnet-5-5` 的 1,000,000 上下文/输入窗口与 128,000 最大输出，以及 `claude-haiku-4-5-20251001` 的 200,000 窗口与 64,000 输出，依据[官方模型规格](https://platform.claude.com/docs/en/models/overview)。4.6 及之后不带日期的模型 ID 是固定版本；更早的浮动别名不进入这张本地表，依据[官方版本规则](https://platform.claude.com/docs/en/about-claude/models/model-ids-and-versions)。详情中的 `max_input_tokens` 和 `max_tokens` 语义依据[官方模型详情接口](https://platform.claude.com/docs/en/api/models/retrieve)，`null` 或示例中的 `0` 保持未知。

Kimi 部分核验日期为 **2026-10-07**。官方 `api.kimi.com` / `api.kimi.ai` 的 `/coding` 服务为 `k3` 提供 1,048,576（1M）上下文与输入上限，为 `k3-256k` 提供 262,144（256K）；最大输出仍未知，读取不到时沿用用户配置。本地表记录模型规格，不再将两个模型统一标记为保守的 256K 值。账户可用窗口仍由套餐权限决定：Plus / Moderato 的 `k3` 可能仅支持 256K，Pro / Allegretto 及更高档位才支持 1M；服务详情和目录报告的可靠字段始终优先。依据[Kimi 官方模型与套餐说明](https://www.kimi.com/code/docs/kimi-code/models.html)。第三方代理即使使用同名模型，也不会套用这些官方静态能力；自定义输入预算取用户上限与已知模型限制的较小值，跟随模型模式则使用已知输入限制及扣除输出预留后的窗口，信息未知时使用备用预算。

### 从 Claude 配置导入模型连接

在「模型与上下文 → 模型连接」点击「从 Claude 默认配置导入」，读取 `CLAUDE_CONFIG_DIR/settings.json` 或用户主目录的 `.claude/settings.json`；也可点击「选择 Claude 配置文件」导入指定 JSON。预览展示来源、服务地址、候选模型与凭据状态，确认前不写入连接、不请求模型。候选模型来自 `model` 和 `env` 中的默认、自定义模型变量；优先采用 `env.ANTHROPIC_MODEL`，其次 `model`，再次 `env.ANTHROPIC_DEFAULT_MODEL`。`sonnet`、`opus`、`haiku`、`fable` 仅在文件含对应具体模型映射时可用于 Native；没有具体 ID 的别名需先补全。

确认导入会将读取的配置转换为自研 Agent 的独立 Anthropic 连接，不修改 Claude Code 默认模型或工作区设置。`ANTHROPIC_BASE_URL` 缺省使用 `https://api.anthropic.com`；配置中的 `ANTHROPIC_AUTH_TOKEN` 使用 Bearer 认证，优先于采用 `x-api-key` 的 `ANTHROPIC_API_KEY`。凭据由主进程读取，不回显，也不把明文写入连接或工作区文件；选择仅本次内存或系统加密保存，前者退出后清除。未配置 API 凭据时可先导入，再在自动展开的连接编辑中补充。回环 HTTP 代理需在预览明确勾选允许。导入就绪后仅显示连接卡片，需要修改时点击「编辑」。

连接列表集中提供新增、导入、编辑和测试入口。「高级设置（价格与本地代理）」「连接与测试说明」默认收起。自研 Agent 新会话的默认连接和模型覆盖位于「新会话默认模型」折叠项，修改后需保存设置；连接本身的操作立即保存。

导入只读取显式配置，不执行 `apiKeyHelper` 或 hooks，也不读取 Claude 登录凭据；源文件不变。项目或组织的多层配置不会自动合并，请选择实际需要的文件。预览五分钟有效且只能确认一次。配置格式、模型优先级与认证规则见 [Claude 设置文档](https://code.claude.com/docs/en/settings)、[模型配置文档](https://code.claude.com/docs/en/model-config)及[环境变量参考](https://code.claude.com/docs/en/env-vars)。Claude CLI 和 Shell 路径、检测及终端显示设置位于「终端与CLI」，工具服务位于「工具与扩展 → MCP 连接」。

Linux `basic_text`、未知或不可用安全后端不允许持久保存密钥，界面提示使用环境变量或内存模式。修改正在运行的连接被拒绝；被会话引用的连接不能删除，可以禁用。连接缺失只阻止受影响会话发起新任务，保留其记录与草稿。

## 能力与限制

提供 `list_directory`、`read_file`、字面量 `search`、单文件 `apply_patch`（创建或完整替换 UTF-8 文本）、`run_command`。修改已有文件必须携带完整内容 SHA-256；创建使用不覆盖并发新目标的发布方式。遇到版本或项目规则变化，拒绝旧审批并要求重新读取。

阶段四新增 `edit_file`：携带完整文件哈希、唯一精确出现的 `oldText` 与替换用 `newText`，只修改该片段。重复匹配、空匹配、无变化或批准后的版本变化会被拒绝；删除片段使用空 `newText`。仍须逐次审批，不自动扩大修改范围。

聊天区显示 native 运行预算、模型窗口来源与服务实际用量。模型窗口和输入/输出限制自动读取，详情、目录及本地能力表按字段补缺。实际输出上限取用户值与模型限制的较小值。输入预算提供「跟随模型窗口」和「使用自定义预算」：前者使用已知模型输入限制及窗口减实际输出预留量的最小值，信息未知时沿用有界备用预算；后者进一步取用户输入上限的较小值。相同限制用于普通发送、发送前和回合内自动压缩、手动压缩；本轮策略快照与有效限制分别保存，重启后可核查来源。预算基于完整协议上下文（含思考与签名）的保守估算，不等于服务端 token 或计费额度；服务未提供用量时保持未知，未配置价格时不显示推算费用。可在模型连接中显式填写某个模型的每百万输入/输出 token 美元价格；仅在实际模型名称一致且服务报告完整输入/输出用量时估算。本回合保存价格快照，修改当前价格不会改写历史；估算不含缓存折扣、压缩请求或其他附加费用。达到预算会停止，不静默丢弃历史。

输入/输出预算、自动压缩、模型重试、每回合模型请求和工具调用次数、运行时长归入全局运行策略。新建 Native 会话跟随设置，首次默认输入模式为跟随模型；旧会话缺少策略标记时继续使用已保存的自定义预算与压缩选项。用户可以明确让旧会话采用全局策略。全局策略仅覆盖这些运行字段，模型连接、模型覆盖、项目 Skills 和 MCP 选择继续保存在会话中。发送和手动压缩开始时固定有效策略，设置修改只影响后续操作，不改变正在运行的请求或历史回合；已有上下文仍绑定原服务、协议与模型，切换需新建会话。审批等待不计入运行时长，模型、工具与摘要共用其余主动时长预算。

连接设置支持用户主动测试已保存的连接：测试可能产生一次小额模型调用，发送固定文本、不带项目内容、不调用工具、不自动重试，可取消。结果仅证明本次所选协议文本请求是否成功；不能据此认定工具调用、长任务或完整 Agent 质量已通过。列表和就绪检查仍只检查本机配置，不主动调用远程服务。

项目规则同时支持 `CLAUDE.md` 与 `AGENTS.md`（2026-09-28 兼容性扩展）：从授权项目/worktree 根到目标目录逐层加载，每层先 `CLAUDE.md`、后 `AGENTS.md`；深层目录优先，同层冲突以 `AGENTS.md` 为准，用户明确指令优先于项目文件。记录完整初始指令、来源、作用域及哈希；任一适用指令变化均使旧审批失效。两种文件共用原有单文件 32 KiB、合计 128 KiB 限制，不会向项目根外爬升，不额外扫描 HOME 或 `.claude` 目录作为全局指令来源，也不执行 URL/include 导入；目标位于项目内 `.claude` 时仍适用一般逐层规则。命令按 cwd 选取规则，无法静态推导任意脚本触及的全部子目录。本次扩展的验证须单独登记，不以历史候选 CI 代替。

P4c 首批提供项目 Skills 的显式选择入口：在「工具与扩展 → 会话工具 → 当前会话」中点击「读取项目 Skills」，勾选并保存，停止后修改、下一回合生效。支持项目根的 `.agents/skills/<名称>/SKILL.md` 与 `.claude/skills/<名称>/SKILL.md`，也可输入其他项目相对 `目录/SKILL.md`，显式读取预览后加入选择；默认发现仍仅扫描前述两个目录。以完整路径区分同名项，默认不启用，最多选择 16 项。可检查正文、哈希和指定目录适用的双项目指令；修改使用编辑器。已选正文与项目指令共用单文件 32 KiB、合计 128 KiB 限制；缺失、危险或超限来源阻止该回合，不静默忽略。Skills 作为任务方法补充，不扩大权限、不自动执行脚本/hooks/includes、不扫描全局来源，也不解释 frontmatter 为执行配置；来源变化使旧审批失效。本批独立验证状态见[项目 Skills 记录](NATIVE-AGENT-PHASE-4C-SKILLS.md)，不表示完整 Claude Skills 兼容。

写入含 `projectSkills` 的新配置后，旧版严格配置校验会拒绝继续该 native 会话；这不表示数据损坏，应保留原数据并使用支持该字段的版本。

MCP 工具支持默认 `2026-07-28` HTTP、显式选择的 `2025-11-25` Streamable HTTP，以及固定 2025 的本地 stdio。先在设置中配置连接，再在「工具与扩展 → 会话工具 → 当前会话」中显式选择（默认空、最多 4 项）。旧连接缺省保持 HTTP / 2026，无自动版本回退。stdio 使用已安装程序的绝对路径、字面参数和主进程环境变量名映射，每回合在启动前单独审批；打开设置、保存和读取列表不会启动程序。每次工具调用仍独立审批；目录与定义计入预算，变化使旧审批失效，未知调用或未确认清理的启动不自动重放。stdio 不是沙箱，程序可访问当前用户资源。共用边界见 [MCP 记录](NATIVE-AGENT-PHASE-4C-MCP.md)，HTTP 兼容见 [2025 记录](NATIVE-AGENT-PHASE-4C-MCP-2025.md)，本批使用、恢复与验证见 [stdio 说明](NATIVE-AGENT-PHASE-4C-MCP-STDIO.md)。含新增配置字段的文件需要支持相应字段的版本读取。

会话侧栏的“在新会话继续”可预览并选择用户/助手可见正文或手写摘要，创建同项目的新会话草稿；明确选择目标引擎后发送才调用服务。不带入工具协议、内部推理或原 conversationId，不自动发送。native `ask_user` 可提出至多三个问题，回答沿用现有提问界面；回答不授予后续工具权限。

本阶段不提供 native 终端、外部原始历史导入、原引擎内部上下文分叉、Claude 命令目录、附件、运行中配置、全局或自动启用的 Skills，也未提供旧 HTTP+SSE、其他历史版本、GET 长连重连、OAuth、tasks、roots、sampling、elicitation 或 resources/prompts。普通下一回合和干净重启续聊使用本地完整协议上下文。已有对话切换服务地址或模型需新建会话。用量使用服务返回值；缺失时不伪造 token、窗口或费用。新增实现与尚未执行的验收详见剩余交付清单，不代表全部服务兼容或真实模型任务已通过。

默认每回合 30 次模型请求、60 次工具调用、10 分钟主动执行时长、5 分钟审批等待、单工具输出 64 KiB；单命令最长 120 秒。完整上下文限制 8 MiB，IPC 消息限制 16 MiB，账本总量默认 256 MiB。token 估计与请求输出上限不能保证远程费用绝对封顶。达到预算即明确停止，不静默截掉历史。

目录互斥覆盖应用登记的 Claude、native 和 Shell：同根或父子目录保守互斥，独立 worktree 可并行。Shell/Claude 终端整个进程生命周期占用目录。队列回执、工作流阶段所有权与物理资源释放分别等待，清理未确认不开放给下一个会话。

这是应用内权限策略，**不是操作系统沙箱**。批准的任意程序可以访问该用户可访问的文件和网络；终端 cd、绝对路径、外部编辑器与共享 Git refs 不受目录锁完整约束。文件哈希是乐观冲突检测，不能抵御所有恶意本机目录替换，也不能保证与外部编辑器并发时绝无冲突。

## 停止、重启和恢复

正常停止会取消模型/审批/工具，排空输出并清理进程树；等待 worker、工具、持久化和投影收尾。Windows 的 native 命令在启动前绑定独立 Job Object：通过原监管进程 IPC 确认身份后绑定，禁止后代脱离该 Job；停止时核查活动进程数为零，并等待助手及监管进程的管道实际关闭。POSIX 使用进程组及存活核查。无法确认资源释放时继续保留占用。Job 只管理正常创建并继承它的后代进程，不构成文件、网络或系统服务的安全沙箱。

每个写入/命令先保存完整模型响应和 `tool_prepared`，完成后保存真实结果。崩溃后只有 prepared、没有 completed 的工具视为未知，不能自动重试。执行已提交但 UI 或队列回执丢失时，相同提交 ID 查询既有结果，不重新调用模型或工具。

未知副作用、损坏记录或未完成的运行会阻断受影响目录。只读会话显示需核查的历史工具：

P4b 会区分可安全收束与结果未知的中断。若没有 prepared 未完成的工具且协议完整，可点击“已核查，恢复会话”：补齐从未执行工具的协议结果后解除此会话的恢复屏障。之后由用户发送新指令继续，不自动续发、恢复队列或重放工具。若仍有未知结果，继续执行下列只读核查流程。

1. 检查文件差异、实际测试结果和残留命令进程，必要时手工停止它们。
2. 在会话中点击「确认已核查执行现场」，阅读主进程确认对话框。
3. 确认只解除目录隔离，原记录和未知工具结果保持只读；新建会话进行后续尝试。系统不会伪造旧工具结果或自动重放。

确认记录绑定账本的具体哈希；记录变化会使旧确认失效。若资源仍未释放或账本损坏，不能用该按钮跳过核查。先保存整个用户数据目录并解决进程/磁盘问题；不要删账本来强行恢复。

P4b 的预算面板提供“压缩上下文（可能计费）”：一次无工具模型摘要请求，保留最初目标、最近完整回合和全部原始记录。摘要可能损失细节，支持取消；失败或新上下文未缩小时不替换上下文。第二批可在配置中主动启用发送前自动压缩，默认关闭；达到本地预算 90% 时尝试一次，失败不隐式重试，计入本次请求次数与运行时长。真实服务表现仍需单独验收。

## 数据与包边界

| 位置 | 内容 |
| --- | --- |
| `packages/agent-core` | 无文件系统/Electron 依赖的端口、顺序工具循环、审批绑定、预算与终态 |
| `packages/agent-node` | Responses / Chat Completions SSE、完整记录库、本地工具、CLAUDE.md/AGENTS.md 项目指令与命令监管 |
| `apps/desktop/src/main/engines/native` | 主进程装配、独立 utilityProcess、窄 RPC、连接凭据、UI 投影 |
| `userData/native/connections.json` | 非秘密连接元数据及可用时的 OS 加密密文 |
| `userData/native/conversations/<UUID>/` | 版本化完整 journal、checkpoint 与单写者锁 |
| `userData/native/recovery-confirmations/` | 用户确认与具体账本哈希 |
| `userData/chat/` | 可从账本重建的展示日志，不是模型上下文来源 |

每回合启动 `dist/native/worker.cjs`。worker 执行 core 和模型适配；main 持有持久记录、实际文件/命令工具和审批。命令使用固定环境变量允许列表，不继承模型密钥、NODE_OPTIONS 或 shell 启动钩子。worker 私有 IPC 接收本回合冻结的凭据；renderer 不得到读取密钥接口。

导出仅包含可见对话/工具内容，排除内部 opaque 推理/续接字段和连接凭据。用户主动批准读取的项目内容仍会进入模型、记录和导出，请据实际内容管理这些文件。正常运行保存完整工具协议结果，未提供的服务内部推理不在承诺范围内。

文件记录执行 fsync；检查点和投影采用临时文件与替换。Windows 的 Node 文件系统接口不提供与 POSIX 相同的可移植目录 fsync 保证，因此不承诺所有断电场景的完全一致语义。损坏或未来 schema 保留原文件并拒绝执行。
