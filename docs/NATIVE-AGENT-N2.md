## 工具用法

原 `search({path, query, caseSensitive?, maxMatches?})` 字面搜索调用保持可用。新增 `find_files`；`search` 可选择 `mode: "regex"`。两者都是只读工具，沿用项目目录、敏感路径、符号链接、宿主目录排除及项目指令规则。

```json
{"path":".","name":"snapshot","glob":"**/*.ts","pageSize":20}
```

上例传给 `find_files`：`name` 匹配文件名中的字面片段，`glob` 限定路径。文本检索示例：

```json
{"path":"apps/desktop/src","query":"session(Status|Id)","mode":"regex","glob":"**/*.ts","ignoreDirectories":["fixtures"],"pageSize":20}
```

`glob` 相对本次 `path` 匹配；不含斜线的模式匹配各层文件名。支持 `*`、`?` 和独占路径段的 `**`，不支持字符组或花括号展开。`ignoreDirectories` 接受字面目录名或项目相对目录路径，不是完整的 `.gitignore` 解释器。正则按行匹配，每行返回首个命中，默认大小写敏感；不把输入当作 shell 命令。具体字段、限制和错误以工具 schema 及返回值为准。

结果包含项目相对路径。`find_files` 只读取文件元数据，因此也能定位普通二进制和超大文件；返回 `hash: null`、`hashStatus: "not_read"`，不能把这个 null 当作允许覆盖现有文件。文本搜索命中包含行、列、摘要及完整文件哈希；列号以原文 UTF-16 单元从 1 计数，`textStartColumn` 说明摘要的起点。编辑前仍需读取相关文件及适用的 `AGENTS.md` / `CLAUDE.md`；搜索命中深层文件不会将该目录指令自动标记为已读。

## 分页与结果完整性

- 返回 `nextCursor` 时，以相同查询参数和该游标取下一页；游标仅属于当前工具实例、运行身份、策略和指令版本，不用于跨回合恢复。
- `scanComplete` 表示限定范围内扫描是否完整，`pageComplete` 表示已到缓存结果末页；只有两者满足时，`complete` 才能为真。
- 扫描达到预算或遇到无法读取的目标时，返回截断原因及范围说明。缓存内结果数不代表整个仓库的真实匹配总数；没有匹配且扫描不完整，不能据此断言目标不存在。
- 分页期间文件或目录版本变化会使旧游标失效，需重新检索。结果是一次有界观察，不是文件系统事务，也不锁住外部编辑。
- 扫描预算耗尽后，结果分页只翻阅已扫描部分；按提示缩小 `path` 或过滤范围重新搜索。不会用游标暗中开启无限扫描。

正则在独立线程中执行，并设时间与内存限制；超时或取消会终止线程并等待退出。游标缓存有数量和内存上限，缓存淘汰后需重查。扫描及分页均复核目录和文件身份，不能通过旧缓存绕过项目边界。

默认上限：每次扫描 4000 个目录条目、8 MiB 读取预算、单个文本文件 1 MiB、目录深度 20、操作预算 10 秒；每个文件的正则匹配限时 200 毫秒，线程启动/语法检查限时 1 秒。缓存最多观察到的 2000 个匹配，每份快照 2 MiB、最多 4 份且总计 8 MiB，游标 5 分钟过期；每页默认 100、最多 1000 条。内存限额按缓存序列化内容记账，线程另有运行时内存限制。

无效编码和二进制读取同样消耗扫描预算。读取前预留文件大小并设单次读取上限，文件在此期间增长会先被拒绝；预算记账可保守高于成功返回的文本字节数。扫描入口位于忽略目录内时直接拒绝，可用显式 `read_file` 处理需要单独读取的普通文件。
