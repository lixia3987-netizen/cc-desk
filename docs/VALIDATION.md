## 桌面启动崩溃排查与回归复验

- 在 Ubuntu 24.04 / Electron 44.4.3 下，用不加载 cc-desk、Playwright 或 node-pty 的最小程序隔离启动阶段：`app.whenReady()`、设置 `nativeTheme` 均正常；`--ozone-platform=headless` 下构造普通 `BrowserWindow`（显示或隐藏）均在构造函数返回前 SIGSEGV；离屏窗口以及 Xvfb / X11 下的普通窗口均能创建、加载页面和退出。DBus / NETLINK / udev 的权限告警在成功组同样存在，不能将这些告警直接认定为崩溃原因。
- 根因落在当前 Electron 的 Ozone headless 普通窗口路径。此前测试在没有 `DISPLAY` 时自动选择该后端，本地行为与 CI 的 Xvfb 不同。新增跨平台桌面测试入口：Linux 无显示时通过 `xvfb-run` 启动 1920×1080 虚拟桌面，已有显示时复用；缺依赖时提示安装 `xvfb` / `xauth`。源码与安装包测试统一 X11 参数，截图脚本也拒绝无显示环境。CI 的源码测试改走同一入口，安装包验证仍由外层 Xvfb 启动。
- 入口保留筛选参数、仓库工作目录和子进程退出码。POSIX 使用独立进程组转发 SIGINT / SIGTERM，真实包装进程与后代的取消测试确认信号均送达、退出码保留、无关进程不受影响。新增 5 项启动测试和最终 TypeScript 检查全部通过。
- Linux Xvfb 下全量运行 39 项桌面用例：首轮 38 通过，1 项“保存并检测 CLI 路径”因后台更新检测也查询版本而使调用次数为 2。仅对该用例的 Electron 进程禁用后台更新，保留“一次检测”和“重试增加一次”的原断言；修复后单独重跑通过。39 项唯一用例均已验证通过，包括 CLI 更新 5 项、Context / 命令 3 项、字体 6 项，以及审批、工作流、原生 PTY、子任务、主题、图表、IDE 和 worktree。
- 当前受限容器使用带临时 Xauthority 凭据的本地 TCP Xvfb 显示，未关闭 X11 认证；正常 CI 使用默认本地传输。已检查 Context 界面读数和布局；容器无中文系统字体，截图不作为中文字形验收，也未覆盖原有文档图片。本轮没有请求真实模型、升级真实 CLI、运行 Windows/macOS 实机或构建发布安装包。下节原先未完成的桌面回归已由本节补齐。
