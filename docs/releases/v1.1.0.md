# cc-desk v1.1.0

本版整理模型与终端设置，增加 Native 工作流阶段验收、累计预算及独立子 Agent。Claude 仍为默认引擎，沿用本机 Claude Code CLI；Native 按会话显式选择并使用独立模型连接。Native 继续标为 **Alpha**，桌面版本号不代表全部真实服务、账号、模型质量或平台人工验收已经完成。

## 模型连接与设置

- 设置按用途分为七类一级菜单及对应二级页面。模型连接、上下文预算、自动压缩集中在“模型与上下文”；CLI、Shell 和终端显示配置位于“终端与CLI”；运行限制、失败恢复和权限位于“运行与权限”。上下文侧栏保留摘要与“会话设置”入口。
- 模型连接页只管理自研 Agent。可读取并预览 Claude Code 配置，将连接地址、模型及凭据来源转换为独立 Native 连接，不修改 Claude Code 配置；Claude 的模型继续由 CLI 管理。Native 支持 Responses、Chat Completions 与 Anthropic Messages。
- 可从已保存连接的服务读取可用模型并选择切换。上下文窗口、最大输入与最大输出 token 按字段优先读取 provider 详情，再读取 catalog 元数据，缺失字段使用有限的本地能力表，并保留来源标识。未知能力保持未知，模型列表不证明服务支持工具或图片。
- 输入预算可跟随已知模型窗口或设置自定义上限，输出预留独立配置。新会话默认跟随已保存策略，旧会话保留原预算；跟随默认的会话在下一轮使用新策略，正在执行的回合保持开始时的配置。
- 修正官方 Kimi Coding 模型能力表：`k3` 为 1,048,576 tokens，`k3-256k` 为 262,144 tokens；可靠服务元数据优先，账号实际权限可能更低。同名第三方代理不直接套用官方静态能力。
- 启动时将已授权的数据目录转换为真实路径，兼容 macOS 临时目录别名和显式指定的数据目录。子 Agent 私有目录以下的符号链接检查继续保留。

设置的保存方式与作用范围见[设置说明](https://github.com/lixia3987-netizen/cc-desk/blob/v1.1.0/docs/SETTINGS.md)，连接与模型能力边界见[Native Alpha 操作说明](https://github.com/lixia3987-netizen/cc-desk/blob/v1.1.0/docs/NATIVE-AGENT-ALPHA.md)。

## Anthropic 内容与模型诊断

- 支持 `thinking`、`redacted_thinking`、思考及签名分片，完整私有内容块保存并按协议续接。兼容 Kimi 缺少签名的思考响应，不伪造签名，也不将思考显示为普通回复。
- 修正缓存用量重新分类的判断：普通输入减少、缓存读取增加时按合并后的总输入检查，允许合法分类变化；非法数值、总量下降和缺少完整终态仍会拒绝。
- 模型错误保存协议、处理阶段与有限枚举原因，帮助区分事件顺序、thinking、工具参数、用量、缺少终态和连接中断。未完整结束的输出不会作为完整结果继续使用；失败不自动切换协议，已产生的操作不自动重放。
- 增加真实服务回归脚本，检查工具续接、思考块、保存后重启及真实连接上的受控断流。报告不记录请求头、服务错误正文或凭据；受控断流属于故障注入，不代表服务自然发生过断流。
- MCP HTTP 显式取消响应流，修复底层流未传递取消信号时超时或关闭仍持续等待的问题。初始化确认与取消通知使用同样的处理，工具取消后的未知结果仍保留，不自动重放。

细节与复现方式见[模型诊断与真实服务回归](https://github.com/lixia3987-netizen/cc-desk/blob/v1.1.0/docs/NATIVE-AGENT-MODEL-DIAGNOSTICS.md)。

## 工作流验收、证据与预算

- 模型连接或 CLI 暂不可用时仍可保存阶段指令草稿；执行按钮继续要求连接就绪，草稿编辑不会启动任务。
- 阶段可选择保持原有完成方式、等待人工确认，或核验 Native 任务条件。运行结束、验收通过和工作流完成分别记录；确认与核验不重新请求模型或执行工具，重启后继续等待。
- 结构化执行回执关联任务与运行身份、修订、工作区、观察到的文件变化、条件、验证证据和实际用量。核验时重新检查当前任务与文件，证据过期、文件变化或身份不匹配会保留等待状态；阶段通过门槛后由用户明确继续。
- 新建 Native 工作流的规划与审阅阶段默认由宿主强制只读，实现阶段使用普通会话审批。只读限制落实到工具准备和执行，不依赖阶段提示词；Claude 保持已有工作流权限语义。
- 可限制整个 Native 工作流的模型请求、工具调用和执行时长。父任务、摘要与子任务共享额度，消耗跨阶段、失败、手动重试、取消和重启保存。排队、阶段间暂停和人工审批等待不消耗执行时长；额度耗尽或用量不完整时停止下发，保留既有产出。

使用与验证边界见[工作流阶段验收与累计预算](https://github.com/lixia3987-netizen/cc-desk/blob/v1.1.0/docs/NATIVE-WORKFLOW-GATES.md)。

## Native 多 Agent

- 增加独立只读审阅与并行实现委派。每次调用可启动 1–4 个子任务，一个父回合最多 16 个；子任务独立模型上下文、worker、任务及运行记录，不能继续委派。
- 只读子任务使用父工作区，仅提供本地读取、搜索及任务记录工具。实现子任务使用独立 Git linked worktree 和分支，可明确选择当前工作区快照或干净 HEAD 作为基线；父分支、索引和文件保持原样。
- 实现委派、写入及命令在父会话审批，并显示子任务与工作区。父任务和所有子任务共享预算；取消父任务会取消子任务并等待相关资源关闭。
- 保留成果补丁、worktree、分支、任务快照与命令回执，界面展示真实状态和路径供审阅，不自动合并或删除。缺少持久终局、未知副作用或清理未确认时保持隔离，重启后不将其当作完成或自动重放。

机制与产物说明见[Native 多 Agent 委派](https://github.com/lixia3987-netizen/cc-desk/blob/v1.1.0/docs/NATIVE-AGENT-DELEGATION.md)。

## 下载与安全升级

发布工作流在三个系统的验证全部成功后，向 Release 上传以下 7 个桌面文件及 `SHA256SUMS.txt` 校验清单：

| 系统 | 安装包 | 便携包 |
| --- | --- | --- |
| Windows x64 | `cc-desk-1.1.0-windows-x64-setup.exe` | `cc-desk-1.1.0-windows-x64-portable.exe` / `cc-desk-1.1.0-windows-x64-portable.zip` |
| macOS arm64 | `cc-desk-1.1.0-macos-arm64-setup.dmg` | `cc-desk-1.1.0-macos-arm64-portable.zip` |
| Linux x64 | — | `cc-desk-1.1.0-linux-x86_64-portable.AppImage` / `cc-desk-1.1.0-linux-x64-portable.tar.gz` |

下载后可按 `SHA256SUMS.txt` 核对文件。GitHub 自动生成的源码压缩包不是桌面应用。“便携”仅指免安装，会话、附件及设置仍默认存放于 Electron userData，不随可执行文件迁移。桌面包包含 Electron 与编译后的 `node-pty`；安装包用户无需 Python 或 Visual Studio C++ Build Tools。Claude 会话需本机 Claude Code CLI，Native 需自己的模型服务与凭据。

升级前备份设置中显示的整个数据目录，并完全退出旧版（包括托盘），再安装或解压新版。保留模型凭据的可用来源；仅存于内存的凭据重启后需要重新设置。升级不会撤销已执行的文件或命令操作，恢复队列及工作流前应检查已有成果。

从 v1.0.0 之前版本升级，首次写入 v3 工作区前仍会保存原始迁移快照。需要降级时，先退出新版，再恢复升级前完整备份或使用独立数据目录；不要让旧版写入新版数据。迁移快照不包含项目与 worktree 文件，详见[迁移与回退记录](https://github.com/lixia3987-netizen/cc-desk/blob/v1.1.0/docs/ENGINE-BOUNDARIES-PHASE-2-VALIDATION.md)。Native 子任务 worktree 和成果不会自动合并或清理，应单独保全需要的项目改动。
