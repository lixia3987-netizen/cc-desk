# cc-desk v1.0.0

本版将双引擎集成成果纳入桌面包：Claude 仍为默认引擎，沿用本机 Claude Code CLI；自研 Native Agent 按会话显式选择，使用独立模型连接。Native 继续标为 **Alpha**，1.0.0 是桌面应用版本，不代表所有真实模型、账号与平台人工验收已经完成。

## 双引擎与 Native Alpha

- Claude 与 Native 使用独立引擎配置，共用项目、会话、任务队列和工作流。已有 Claude 原生终端及 Shell 会话继续可用；未知引擎保留配置与已有展示记录，不自动切换为 Claude。
- Native 支持 Responses / Chat Completions 连接、独立 worker、持久任务计划与证据、本地文件读取与检索、逐次审批的文件编辑和命令执行。长命令可在当前回合启动、查询状态、读取输出和停止。
- 支持项目 `AGENTS.md` / `CLAUDE.md`、显式项目 Skills，以及 MCP HTTP / 本地 stdio 工具。stdio 使用已安装程序的绝对路径与字面参数，每回合启动与每次工具调用分别审批。
- 支持显式图片输入、本地预览与输入框粘贴。含图会话可压缩首张图片之前的完整纯文本前缀，保留图片及之后的内容；可预览压缩范围。自动压缩默认关闭。
- 工具与任务状态持久保存。中断或崩溃后的未知副作用保持只读，不自动重放文件、命令或外部工具操作。Native 命令使用当前用户权限，不提供操作系统沙箱。

Native 不需要 Claude CLI 登录，需要自行配置兼容模型连接与凭据。使用方法见 [Native Alpha 操作说明](https://github.com/lixia3987-netizen/cc-desk/blob/v1.0.0/docs/NATIVE-AGENT-ALPHA.md)，功能与实际验收边界见 [正式验收台账](https://github.com/lixia3987-netizen/cc-desk/blob/v1.0.0/docs/NATIVE-AGENT-RUNTIME-ACCEPTANCE.md)。

## 桌面会话与流程

- 普通新建会话先编辑任务与配置，首次发送时才建立结构化会话；跨引擎承接先形成待确认草稿，不自动发送。
- 结构化消息保存后即可继续输入与排队；可将指定排队消息立即发送。停止、失败或重启后暂停剩余队列，保留消息供检查后手动继续。
- 右侧上下文、变更、工作流和诊断面板独立开关，可同时显示，宽窗口最多两列，窄窗口单列滚动。
- Claude 上下文用量按每轮发起时选择的模型计算，改善模型路由返回不同名称后的容量显示。CLI 更新只维护 Claude，暂停其队列并释放相应资源，其他引擎和 Shell 继续运行。
- 保留会话自动命名、工程路径筛选、连接管理、随机 Worktree 名称与起始分支选择，并将初次发送前的图片暂存纳入双引擎流程。

本版集成范围与开发验证见 [Native / main 集成记录](https://github.com/lixia3987-netizen/cc-desk/blob/v1.0.0/docs/NATIVE-AGENT-MAIN-INTEGRATION.md)。

## 下载与升级

Release 的 Assets 提供以下 7 个桌面文件，以及 `SHA256SUMS.txt` 校验清单：

| 系统 | 安装包 | 便携包 |
| --- | --- | --- |
| Windows x64 | `cc-desk-1.0.0-windows-x64-setup.exe` | `cc-desk-1.0.0-windows-x64-portable.exe` / `cc-desk-1.0.0-windows-x64-portable.zip` |
| macOS arm64 | `cc-desk-1.0.0-macos-arm64-setup.dmg` | `cc-desk-1.0.0-macos-arm64-portable.zip` |
| Linux x64 | — | `cc-desk-1.0.0-linux-x86_64-portable.AppImage` / `cc-desk-1.0.0-linux-x64-portable.tar.gz` |

桌面包已包含 Electron 与编译后的 `node-pty`，使用安装包无需安装 Python 或 Visual Studio C++ Build Tools；从源码安装依赖或自行打包仍需相应构建工具。Claude 会话仍需本机 Claude Code CLI，Native 会话需独立模型连接。

升级前备份设置中显示的数据目录，并完全退出旧版（包括托盘），再安装或解压新版本。数据目录不变，“便携”仅指免安装；数据不会随可执行文件自动迁移。GitHub 自动生成的源码压缩包不是桌面应用。

本版引入带版本的 `engineConfig` 与 v3 工作区数据，首次写入 v3 前保存独立原始迁移快照。旧版不能写入 v3 数据；需要降级时，先退出新版，再恢复升级前备份 / 迁移前快照，或使用独立数据目录。详见 [数据迁移与回退记录](https://github.com/lixia3987-netizen/cc-desk/blob/v1.0.0/docs/ENGINE-BOUNDARIES-PHASE-2-VALIDATION.md)。恢复后须检查已产生的文件与命令操作，再手动继续队列。

## 验证与使用边界

发布流程要求 Windows x64、macOS arm64 和 Linux x64 的检查、桌面测试、打包及实际包启动验证全部成功后上传资源。具体结果以本 Release 附带的源提交和 Actions 记录为准。日常推送、PR 与合并不自动运行 CI；本次按明确发布请求手动构建。

自动测试使用本地模型 / CLI 协议测试进程，不代表真实模型质量、全部服务兼容性、真实 Claude 账号或操作系统凭据后端均已验收。[正式验收台账](https://github.com/lixia3987-netizen/cc-desk/blob/v1.0.0/docs/NATIVE-AGENT-RUNTIME-ACCEPTANCE.md)中的未完成项保持原状态，三平台工作流证据与人工验收分别记录。

- 安装包未签名 / 公证；macOS 仅提供 Apple silicon arm64。Windows 单文件便携启动器、Linux FUSE 挂载与真实系统安全提示仍需实机验收。
- cc-desk 桌面应用需手动升级，内置更新仅更新本机 Claude Code CLI。
- 客户端不是 Anthropic 官方产品，不附带模型服务或账户。
