# cc-desk v0.3.0

本版整合自 v0.2.2 以来的桌面体验更新：按项目管理会话，看清子任务执行进度，减少会话切换和连续输入时的打断。沿用本机 Claude Code CLI 的账户、模型与 provider 配置，保留结构化对话和原生终端两种使用方式。

## 会话更有序，执行状态更清楚

- **按项目分组**：侧栏支持项目折叠、项目 / 会话搜索和项目内直接创建；紧凑标题栏增加消息阅读空间，右侧面板可随时收起，重启后保留显示偏好。
- **自动命名**：新建 Claude 会话名称留空，首条有效消息自动提取短标题，不额外请求模型。显式名称和手工重命名不会被覆盖，旧会话、导入及分支保留原名。
- **子任务进度**：输入区上方显示总数、进行中、已完成和异常数量；展开查看任务说明、最近工具、进度、耗时及结果摘要，可切换当前轮 / 全部记录。结构化对话和受支持的原生终端 hooks 均可记录，右侧面板收起后仍可查看。
- **回合完成状态修复**：不再将空闲 CLI 进程当成正在执行的任务。结构化回合完成后，顶栏回到继续输入，隐藏中断和停止按钮；创建或管理 worktree 等操作可释放确认空闲的结构化进程，后续仍恢复原对话。

子任务只展示 CLI 实际报告的数据，重复事件不重复计数，后台启动确认不等于完成。未上报的指标留空；重启后未确认完成的任务标为中断。旧消息不会被用来猜测历史任务数量，每个会话最多保留 200 条任务记录，超出时明确提示统计不完整。

## 输入、阅读与切换

- **Enter 发送，Ctrl+Enter 换行**；也支持 Cmd / Shift+Enter 换行。中文输入法选字、重复按键和连续换行有保护。原生终端上方编辑器在状态已同步且 CLI 支持时可直接发送，否则保留粘贴后在终端确认的流程。
- **五套主题**：森野绿、云白靛、暖砂陶、极夜蓝、墨黑琥珀，覆盖对话、终端、代码、Git 差异与弹窗；可预览、取消、保存，切换不重启正在运行的终端。
- **Mermaid 图表**：消息、工具结果和工作流摘要中的 Mermaid 支持预览 / 源码切换、复制与主题同步；流式内容未完成或语法错误时仍可查看源码。
- **对话检索**：Ctrl / Cmd+F 搜索本地保留的消息，定位原文并展开对应工具卡片；支持旧消息分页和同次运行内的阅读位置恢复。
- **统一待处理入口**：顶栏汇总各项目有效的审批与提问，点击直达；已响应、取消或过期的请求及时移除。
- **草稿与连续操作**：工作流目标、阶段指令和按文件保存的审阅意见可跨切换 / 重启恢复；模板追加不覆盖已有输入。新建会话使用正确项目，Git 在回合结束及重新聚焦后刷新，保留审阅内容。

## 按自己的环境配置

- **默认权限与 Bypass**：支持按需审批、Plan、接受编辑和 Bypass，可保存新会话默认模式并逐会话覆盖。Bypass 允许工具直接修改文件与执行命令，CLI 的强制限制和需要用户回答的提问仍然生效。
- **指定 IDE**：选择 VS Code、WebStorm 或定制版应用，顶部入口直接打开当前会话的实际工作目录，包括独立 worktree。
- **Worktree 位置**：默认在项目的 `.claude/worktrees/` 下创建，也可选择统一目录；按项目和自定义名称组织，附短标识避免重名。设置变化只影响新建目录，既有 worktree 继续按原路径恢复与管理。
- **CLI 检测**：「保存并检测」使用当前填写的路径，支持标准 Windows npm 安装布局；保留新版原生入口和旧版 Node.js 入口兼容。

本版同时保留 v0.2.2 的回复去重、审批等待、历史恢复、附件草稿和退出清理修复。

## 验证与使用边界

发布流程要求 Windows、macOS 和 Linux 的检查、桌面测试、打包及包内程序启动验证全部通过，再上传并核对 Release 文件。具体结果以本 Release 附带的源提交和 Actions 记录为准；详细开发验证见[验证记录](https://github.com/lixia3987-netizen/cc-desk/blob/v0.3.0/docs/VALIDATION.md)。

自动验证使用本地协议 / PTY 测试进程，不代表真实 Claude 账户、所有 CLI 版本或模型服务均已验收。实际包验证覆盖 Windows 安装版 / ZIP、macOS DMG / ZIP、Linux tar.gz / 提取的 AppImage；Windows 单文件便携启动器、Linux FUSE 挂载、系统签名与公证提示仍保留已有实机验收边界。

原生终端完成回合后显示「关闭终端」；终端仍可能保有后台命令或未发送输入，创建关联 worktree 前需要关闭。自动释放空闲进程仅适用于已确认空闲的结构化会话，不会释放仍在执行、等待审批或有后台任务的会话。

GitHub Actions 继续仅手动触发，日常推送和 PR 不会自动构建或发布。
