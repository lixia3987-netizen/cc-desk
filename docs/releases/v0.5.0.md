# cc-desk v0.5.0

本版整合 v0.4.0 之后的三项更新：结构化消息队列、可独立打开的右侧面板，以及按消息发起模型计算的上下文容量。

## 连续输入与消息队列（PR #19）

- 消息和附件保存成功后立即清空对应输入，无需等 Claude 执行完毕；保存失败保留草稿，提交期间新输入的内容不会被旧请求清空。
- 任务执行期间可继续发送，每个会话按顺序排队。队列显示消息内容与附件，可移除尚未发送的消息；重复提交同一请求不会重复入队。
- 悬停或聚焦排队消息后点击「立即发送」，中断当前任务，等待本轮、工作流及进程资源释放后优先执行所选消息；其余排队消息保留顺序。
- 队列及附件关联保存在本机。执行失败、用户停止、应用重启或 CLI 更新时暂停队列，保留待处理消息供检查后手动继续；不会静默重试可能已经产生操作的消息。

队列适用于结构化聊天；原生终端沿用现有发送方式。中断不会撤销已执行的命令或文件修改。斜杠命令同样排队，不能附带附件。

## 右侧面板独立打开与自动布局（PR #18）

「上下文 / 变更 / 工作流 / 诊断」各自拥有开关，可以同时打开多个面板、分别折叠内容或关闭。根据可用宽度自动采用双列或纵向排列，每个面板独立滚动；关闭全部面板后保留工具栏，也可整体收起右侧区域。

打开、折叠和整体显示偏好在本机保存，切换会话或重启后沿用。布局调整保留当前输入及 Git 审阅、工作流草稿，不重启正在运行的终端；运行配置仍需点击「保存配置」才会保存。

## 按发起模型保持上下文读数（PR #20）

- 每条消息实际开始执行时绑定当前 CLI 选择的模型，排队时不提前绑定；整轮按该模型查询窗口容量。ccSwitch 等路由返回不同模型名，以及工具续轮中的名称变化，不再导致已知容量和占比消失。
- 输入 token 仍按最新主会话请求刷新，包含缓存读取与写入；累计用量与子任务用量不叠加为当前占用。后续事件缺失用量或容量时保留上次有效读数，详情显示「上下文计算模型」。
- 窗口容量只使用匹配模型的 CLI 元数据或已保存的 `/context` 报告，不根据模型名称猜测。显式换模型后重新绑定；`/clear` 清除旧用量和报告，压缩后保留容量并等待下一次请求更新用量。

使用说明见[上下文与命令](https://github.com/lixia3987-netizen/cc-desk/blob/v0.5.0/README.md#上下文用量与--命令)。

## 验证与使用边界

发布流程要求 Windows、macOS 和 Linux 的检查、桌面测试、打包及实际包启动验证全部成功后上传资源。具体执行结果以本 Release 附带的源提交和 Actions 记录为准，开发验证见[验证记录](https://github.com/lixia3987-netizen/cc-desk/blob/v0.5.0/docs/VALIDATION.md)。自动测试使用本地协议与 PTY 测试进程，不代表真实 Claude 账户、全部 CLI 版本或模型服务均已验收。

- 包未签名 / 公证，macOS 仅提供 Apple silicon arm64。Windows 单文件便携启动器、Linux FUSE 挂载和真实系统安全提示仍需实机验收。
- cc-desk 桌面应用仍需手动升级；内置更新功能仅更新本机 Claude Code CLI。Claude `settings.json.env` 中的代理尚未转发给应用的更新检查，会话可用不代表更新元数据可达；检查失败不会断开工作区或开始安装。
- 使用前需安装并登录本机 Claude Code CLI；cc-desk 不是 Anthropic 官方产品，不附带模型服务或账户。
