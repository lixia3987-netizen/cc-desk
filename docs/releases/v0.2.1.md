# Claude Workbench / cc-desk v0.2.1

修复 Windows 上 npm 安装的 Claude Code 无法检测、提示“CMD/BAT 启动器无法安全解析”的兼容性问题。

## 本次修复

- 读取 `@anthropic-ai/claude-code/package.json` 声明的实际入口，不再固定查找旧版 `cli.js`。
- 新版 npm 包的 `bin/claude.exe` 直接启动，不要求运行时有 Node.js；旧版 JavaScript 入口优先使用启动器同目录的 `node.exe`，其次查找 PATH。
- 兼容标准 npm 全局安装、自定义 prefix、项目 `node_modules/.bin`，以及包含空格/中文的路径、带引号的路径和 Windows PATH 大小写。
- 检测、结构化会话、原生终端和诊断统一使用入口解析；错误提示区分安装包信息无效、入口文件缺失和旧版缺少 Node.js。
- 不执行任意 CMD/BAT 内容，不通过命令 Shell 拼接参数；保留对未知安装布局和不支持入口的拒绝。

这是单独的 Windows npm 兼容性维护版；之前优化检查报告中的进程清理、Worktree、历史性能等项目仍待后续修复。

## Windows 更新与使用

在 Assets 下载以下任一种：

| 文件 | 用途 |
| --- | --- |
| `cc-desk-0.2.1-windows-x64-setup.exe` | 安装版 |
| `cc-desk-0.2.1-windows-x64-portable.exe` | 单文件便携版 |
| `cc-desk-0.2.1-windows-x64-portable.zip` | 解压完整目录后运行 |

完全退出旧版（包括托盘实例），再安装或运行新版。现有默认用户数据目录和数据格式不变。

打开“设置与连接”重新检测。若自动发现失败，在 PowerShell 执行 `where.exe claude`，将列出的 `claude.cmd` 或 `claude.exe` 完整路径填入 CLI 路径。无需把 `.cmd` 改名为 `.exe`。旧版 JavaScript 包仍需要 Node.js；更新 PATH 后应完全退出并重开工作台。

若提示 npm 启动文件缺失，请先确认终端里的 `claude --version` 能运行，再修复 CLI 安装。此版本不会自动重装 CLI 或修改 Claude/provider 配置。

- Windows CI 实际安装固定版本 `@anthropic-ai/claude-code@2.1.278`，验证显式路径和自动发现，以及 `--version` / `--help`。不发模型请求。
- 三平台构建、测试和打包通过后才发布；具体执行结果见本 Release 附带的构建记录。

- 包仍未签名/公证，无自动更新。“便携”指免安装，数据默认保存在用户数据目录。
